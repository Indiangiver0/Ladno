## QA008-OCR01 — P1, подтверждено, открыт

Автор этого QA создал `ReceiptLayoutRuntimeTest.java` до сборки: неизменяемый независимый PNG bitmap с текстом `PAID / TOTAL / 754.32 KZT / 2026-11-03`, строгие ожидания754.32. Root выполнил настоящий Android instrumentation на отдельном Ladno_QA_API30/API30/x86_64. Я прочитал сохранённые command/private JSON: actual Tesseract вернул **794.32**, `meanConfidence=94`; ReceiptParser кандидат **high**, amount794.32. Assertion expected754.32 vs actual794.32 завершился FAIL. Исходные текст/ожидание не менялись для получения PASS.

Production NativeRuntime считает mean≥80 достаточным техническим gate и при однозначном paid/date/currency направляет такой high кандидат в автопост. Это подтверждает недостаточность проверки OCR для денежных сумм. Сам native ingest данного fixture не выполнялся: тест корректно остановился на первом неверном actual amount. Нельзя объявлять проведённый фактический расход794.32, но автоматический путь допускает его по текущему коду. Root присвоил QA008-OCR01 и вернул native-отделу. Сырые синтетические свидетельства сохранены в `before-ocr-fix/`.

Следующие RU fiscal/unpaid изображения и native media assertions этого запуска **не выполнены** из-за fail-fast. После исправления нужен повтор того же неизменённого изображения/ожиданий и проверка затронутых отрицательных/повторных случаев. Текущий APK к приёмке не рекомендован.
