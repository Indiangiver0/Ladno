## Граница WebView → Java

- Android документирует: `addJavascriptInterface` открывает объект всем фреймам, origin вызывающего фрейма не проверяется. Следовательно, bridge допустим только при гарантированно доверенном содержимом без чужих HTML/iframe; package/no-INTERNET сами по себе не предотвращают локальный XSS. [Native bridges](https://developer.android.com/privacy-and-security/risks/insecure-webview-native-bridges).
- `AndroidApp.request` — единственный минимальный `@JavascriptInterface`: конечный action whitelist из CONTRACT, строгая JSON-схема/типы/длины/число элементов, неизвестное отклоняется. Native повторно проверяет money/currency/date/category/source IDs и существование объектов; JSON не задаёт SQL, путь, URL, имя Java-метода, JS или callback. SQL — фиксированные запросы с bind arguments; ошибки — безопасные коды без исходного JSON.
- Additive поле `permissions.notificationError` — optional `null|Error={code,message,field}` с безопасным сообщением без raw; отсутствие поля у старого state эквивалентно null. Это ошибка capture/защищённой идентификации, а не доказательство отсутствия банковской операции; notificationAccess отражает OS-доступ отдельно.
- Bridge работает на внутреннем background thread WebView: сериализовать изменения SQLite, не вызывать UI/camera/settings напрямую с него. UI-действия — через Activity/main thread, OCR — отдельный single worker с ограниченной очередью; не блокировать UI распознаванием. [WebView API](https://developer.android.com/reference/android/webkit/WebView#addJavascriptInterface(java.lang.Object,%20java.lang.String)).
- HTML/CSS/JS только из заранее перечисленных APK assets `www`; загружать фиксированный `https://appassets.androidplatform.net/www/index.html`. В native interception проверять scheme/host/port/userinfo и точный разрешённый path; не использовать startsWith(host), произвольный AssetManager path или маппинг на private files. Неизвестный ресурс/метод/путь/encoding → непустой deny-response, без сетевого fallback. Локальная HTTPS-схема поддерживает same-origin; стандартный AssetLoader при неизвестном ресурсе допускает сеть. [Load local content](https://developer.android.com/develop/ui/views/layout/webapps/load-local-content).
- Все внешние navigation/deep links, `intent:`, `file:`, `content:`, `data:`, `javascript:`, `blob:`, subframes, popups/downloads блокировать; native `loadUrl` принимает только фиксированную страницу. `shouldInterceptRequest` не видит javascript/blob/file-asset URL и последующие redirect URL; `shouldOverrideUrlLoading` не покрывает app-initiated loadUrl и POST. Один callback не служит полной изоляцией. [WebViewClient API](https://developer.android.com/reference/android/webkit/WebViewClient).
- Явно отключить `allowFileAccess`, `allowContentAccess`, file-URL/universal file access, автоматические окна и multiple windows; `blockNetworkLoads=true`, `MIXED_CONTENT_NEVER_ALLOW`, cleartext запрещён, INTERNET отсутствует в итоговом merged manifest. `onReceivedSslError` всегда cancel, никогда proceed; debugging WebView выключен для передаваемого APK. [WebSettings](https://developer.android.com/reference/android/webkit/WebSettings), [SSL handler](https://developer.android.com/reference/android/webkit/SslErrorHandler).
- CSP для локального UI разрешает лишь необходимые собственные статические scripts/styles/images, запрещает frames/objects/connect/base/form actions; без unsafe-eval/unsafe-inline и внешнего CDN. Запрет file/content в WebView не распространяется на законное native-чтение выбранного пользователем URI.
- Financial/user/OCR/notification text вставлять через `textContent`/DOM properties, не innerHTML, eval, JS-template interpolation или обработчики из строк. Native→JS только фиксированный refresh-сигнал без данных/имени функции из входа; UI запрашивает JSON-состояние через bridge. Ошибочные строки вроде `</script><img onerror=...>` остаются текстом.

## Камера, изображения и OCR

- Запускать camera/gallery только native Activity по действию пользователя: Photo Picker/выбор документа возвращает выбранный URI; камера пишет в заранее созданный private output через узкий FileProvider grant. Bridge не принимает произвольный URI/путь и не открывает file chooser WebView. CAMERA запрашивается только при прямом доступе к камере; `ACTION_IMAGE_CAPTURE` с внешней камерой не требует собственного CAMERA. [Permissions alternatives](https://developer.android.com/privacy-and-security/minimize-permission-requests), [Photo Picker](https://developer.android.com/training/data-storage/shared/photo-picker).
- Проверять URI grant, MIME/реальное декодирование, предельные bytes/dimensions/pixels/строки и доступную память; неизвестный размер не отменяет byte cap при чтении. Декодирование с downsample, отмена/ошибка/потеря grant завершаются без фиктивной операции. Числовые пределы обязаны появиться в CONTRACT/коде как технические лимиты и проверяться на границах.
- В реализации требуется фактический локальный Tess4Android single worker, только eng/rus/kaz traineddata из проверенных APK assets, копируемых в доступный движку private каталог; никаких путей/моделей/команд/языковых имён из bridge. Испытать init failure, отсутствие/повреждение модели и повторный запуск; наличие модели не доказывает качество распознавания. Не выполнять QR/URL/notification actions, найденные в источнике.

## Уведомления, метаданные и ARC-01

- NLS включается/отзывается пользователем в системных настройках; это широкий OS-доступ, не permission «только банки». Локальный allowlist package/profile проверять до извлечения title/text/extras; посторонние события отбрасывать без сохранения/логов. `POST_NOTIFICATIONS` относится к собственным уведомлениям. [NLS](https://developer.android.com/reference/android/service/notification/NotificationListenerService), [POST_NOTIFICATIONS](https://developer.android.com/develop/ui/compose/notifications/notification-permission).
- Банковские labels/иконки/текст не являются идентичностью приложения; уведомление не является банковским архивом или доказательством окончательного списания. Неполные/неизвестные сообщения идут в review; после разрыва сбора не заявлять полноту. Android15 OTP-redaction, work profiles и Restricted Settings сохраняются; обходов через accessibility/root/скрытые банковские данные нет. [Android15 OTP](https://developer.android.com/about/versions/15/behavior-changes-all#otp-redaction), [CDD](https://source.android.com/docs/compatibility/15/android-15-cdd).
- READ_SMS/RECEIVE_SMS и прямое чтение inbox не входят в APP-005 notification-путь без отдельного решения пользователя. Уведомление выбранного SMS-приложения — лишь показанное им содержимое; sender/текст остаются недоверенными. [SMS permission](https://developer.android.com/reference/android/Manifest.permission#READ_SMS).
- ARC-01 / P2, проектная неоднозначность: raw notification key/tag/source IDs/account могут содержать заданный источником чувствительный текст. Запрет raw распространяется на метаданные, exception, evidence и диагностические ID, а не только title/text. В памяти raw используется для обработки, но в SQLite/UI/debug/backup не сохраняется произвольной строкой.
- Исправление ARC-01 в контракте: durable `sourceKeyToken`, `revisionToken`, `accountSurrogate`, `paymentRefToken` — HMAC-SHA256 со своим per-install Android Keystore key, отдельным purpose, namespace package/profile и однозначным length-prefixed encoding. Raw key/tag/account/reference не хранить даже в таблице соответствий. Перед storage ingress transient paymentReference преобразуется в token либо остаётся неизвестной identity, затем typed candidate содержит явный `paymentReference:null`; storage отклоняет nonnull raw. Ключ и вход HMAC не логировать. [Keystore](https://developer.android.com/privacy-and-security/keystore).
- Для дедупликации сохранять tokens, безопасные package/profile IDs, postTime/capturedAt, lifecycle/revision и связи event/candidate/transaction в локальной БД; их срок — пока нужны сохранённой записи, без бессрочного raw. OS key/postTime и HMAC текста сами по себе не transaction identity; потеря ключа/наблюдения → review. Raw очищается независимо от необходимых безопасных доказательств идемпотентности.

## Локальное хранение и новая установка

- В реализации SQLite и временные исходники должны находиться в private internal storage, runtime INTERNET должен отсутствовать. OTP/PIN/банковские пароли/полные счета не нужны и не входят в сохраняемые поля. Source text/image/URI/account/raw tags/суммы не попадают в logcat/краш-логи/тестовые отчёты; только safe code/stage/internal random ID. [Internal storage](https://developer.android.com/training/data-storage/app-specific).
- ARC5-03: полный OCR/notification text только transient, не durable и не в JS/state/review. Разбор хранит структурированный кандидат/reasons и безопасную provenance. Только private temporary image имеет engineering default ≤24ч, очистку после обработки/cancel и startup cleanup; исходную фотографию пользователя не удалять. После очистки недоступен повторный OCR оригинала. TTL — техническое решение, а не пожелание пользователя; фактическая очистка при сбоях требует device проверки.
- Уведомление/чек/ручной ввод проходят общую native-валидацию и атомарное проведение; редактирование/category-null не создаёт второй расход. Исключения SQLite/OCR не возвращают ложный успех; источник/кандидат/денежная запись остаются различимыми. Точные money/валюта/дата задаются CONTRACT, без float и угадывания валюты.
- ARC5-05: local/no-transfer требует исключить финансовую БД/очередь/исходники из cloud, D2D и отдельно cross-platform-transfer на поддерживающих ОС Android16QPR2/36.1+: правила режимов не наследуются. Не выдумывать iOS bundle/team ради XML; применять поддерживаемый запрет export/restore и проверять каждый транспорт отдельно. Один allowBackup/cloud/D2D policy не доказывает OEM/cross-platform запрет; private storage автоматически может резервироваться. Потеря устройства без экспорта угрожает потере локального учёта. [Auto Backup](https://developer.android.com/identity/data/autobackup).
- Новая установка содержит пустую БД и onboarding для валюты/timezone/явной date policy, без demo операций/KZT по умолчанию. Источники по умолчанию не выбраны. Для папы отдельная установка/данные; общий бюджет и cloud sync не добавляются.
