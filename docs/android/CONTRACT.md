## Bridge и envelope

Единственный JS→native метод: `AndroidApp.request(String action, String payloadJson): String`. JS передаёт JSON object; все неизвестные actions/поля, неверные типы, payload >65536 UTF-8 bytes отклоняются.
Успех: `{"ok":true,"data":{...},"error":null}`; ошибка: `{"ok":false,"data":null,"error":{"code":"VALIDATION","message":"Безопасный текст","field":null}}`. `data` всегда объект, `field` null либо имя поля, сырые входы/stack trace в message не попадают.
Whitelist ровно: `state`, `settings`, `saveTransaction`, `deleteTransaction`, `saveCategory`, `deleteCategory`, `saveSources`, `reviewCandidate`, `scanCamera`, `scanGallery`, `openNotificationAccess`.
JSON null явный; absent допускается только у явно optional полей. Денежные значения — только строки, revisions/scale/counts — целые JSON numbers; IDs — непрозрачные native-generated UUID, не номер счёта/уведомления.
`request` выполняется на bridge worker thread; storage синхронен/сериализует записи, UI intents идут main thread; OCR — отдельный single worker. Успех mutation возвращается после SQLite commit.

## DTO state и денежные значения

- `Transaction={id,revision,kind,date,amount,currency,scale,categoryId,note,source,createdAt,updatedAt}`; kind `income|expense`, source `manual|notification|receipt`, categoryId `null|UUID`, note string, timestamps UTC ISO8601.
- `Category={id,revision,name,kind}`; kind `income|expense`, name trim 1..80 Unicode chars; категория должна соответствовать виду операции. Native timestamps/revisions/scale/source не принимаются из формы редактирования.
- `Settings={initialized,primaryCurrency,zoneId,datePolicy}`; до setup значения кроме initialized=false равны null. После setup primaryCurrency — ISO code, zoneId — валидный `ZoneId`, datePolicy строго `POST_TIME_IN_ZONE`.
- `Currency={code,scale}`; каталог `java.util.Currency` с известным defaultFractionDigits 0..6, без undefined(-1), сортировка по code. Primary currency выбирается явно, KZT/валюта телефона не подставляется; изменение primary не конвертирует записи.
- amount DTO — положительное canonical decimal без знака/группировки/экспоненты/ведущих нулей (кроме `0.xxx`), ровно scale дробных цифр; scale0 без точки. Максимум 24 цифры целой части; нулевая операция отклоняется.
- Manual amount input ≤64 chars, ASCII-цифры и максимум один decimal separator точка/запятая без группировки; ведущие нули, пробелы, знаки, пустая дробь/ввод запрещены. Native нормализует `1,2`→`1.20` при scale2; любые лишние дробные цифры, включая нули, отклоняются ДО `setScale(UNNECESSARY)`.
- В core BigInteger minor (или точный BigDecimal без округления), SQLite TEXT canonical amount; нельзя float/double/JS Number/parseFloat/SQL SUM для денег. UI форматирует строки; primary currency не восполняет неизвестную валюту источника.
- `date` — operationDate, строгая реальная `YYYY-MM-DD`, годы0001..9999; `month` — `YYYY-MM`. Итоги месяца по `[первый день, первый день следующего)` сохранённых дат, отдельно по currency; createdAt/capturedAt не меняют период.
- `Summary={month,currency,scale,income,expense,net}`: canonical строки, income/expense≥0, net может быть отрицателен; categoryId=null входит в expense. Лимит24 цифры относится к вводу операции, агрегаты не обрезаются; нет выдуманного банковского баланса, конвертации или сложения валют.
- `Import={id,revision,status,source,sourceLabel,receivedAt,kind,amount,currency,scale,date,dateOrigin,note,reasons,confidence,transactionId,possibleMatchIds}`; status `needs_review|posted|linked|ignored`, confidence `high|uncertain|unavailable`.
- Import kind `income|expense|null`, денежные/date поля и transactionId допускают null, note — нормализованная безопасная заметка ≤500 chars, reasons — массив кодов, possibleMatchIds — UUID сохранённых операций; raw OCR/title/text в Import отсутствует.
- `dateOrigin=source|post_time|user|null`; отсутствие банковской даты разрешает postTime в сохранённой zoneId только после явного setup/datePolicy. Отсутствующий postTime/дата чека, неоднозначные дата/валюта/сумма требуют review.
- `state` data: `{schemaVersion:1,settings,currencies,selection:{month,currency},records,categories,imports,sources,summary}` плюс native поля ниже. records — неудалённые операции выбранных month/currency, date DESC/createdAt DESC/id; categories — все, imports — все needs_review глобально.
- ARC5-04: records/imports/summary и прочие DB-поля state читаются одним согласованным SQLite snapshot либо под общей сериализацией с execute/ingestCandidate; параллельный listener commit не может разъединить список и денежный итог.
- `sources` — массив выбранных packageName strings (изначально `[]`), не строковые raw source IDs. selection.currency/summary равны null до setup; records/imports/categories изначально пусты. При setup summary выбранной валюты — точные нули её scale.
- Native добавляет к state `permissions:{notificationAccess:boolean,cameraGranted:boolean,notificationError?:null|Error}`, `packages:[{packageName,label,selected}]`, `ocr:{ready:boolean,languages:["eng","rus","kaz"],error:null|Error}`, `jobs:[Job]`, `suggestedZoneId:string`.
- `permissions.notificationError` — optional безопасная sticky ошибка приёма/переполнения уведомлений, без raw содержимого; отсутствующее поле трактуется как null. UI Settings/Imports показывает callout при nonnull, обычный refresh сам не скрывает ошибку и не выдаёт неполный приём за полный.
- packages — доступные launcher приложения; selected вычисляется по sources. Label не доказывает принадлежность банку. Store не делает PackageManager/permission запросов; native не подменяет DB state демонстрацией.

## Actions: точные payload → data

- `state`: `{month?:string|null,currency?:string|null}` → state выше. null/absent month = текущий месяц сохранённой zoneId (до setup suggestedZoneId), currency = primaryCurrency; явные фильтры проверяются.
- `settings`: `{primaryCurrency:string,zoneId:string,datePolicy:"POST_TIME_IN_ZONE"}` → `{settings:Settings}`; первоначальное подтверждение должно явно показывать валюту, зону и правило даты. Все actions кроме state/settings требуют setup, иначе SETUP_REQUIRED.
- `saveTransaction`: `{id:null|UUID,expectedRevision:null|int,kind,date,amount,currency,categoryId:null|UUID,note:string}` → `{record:Transaction}`. id=null/revision=null создаёт; update требует ожидаемую revision; source/provenance существующей записи сохраняются.
- `deleteTransaction`: `{id:UUID,expectedRevision:int}` → `{id:UUID,deleted:true}`; soft delete, исходные связи/токены сохраняются, повтор события не воскрешает запись.
- `saveCategory`: `{id:null|UUID,expectedRevision:null|int,name:string,kind:"income"|"expense"}` → `{category:Category}`. Изменение kind используемой категории отклоняется REFERENCE_CONFLICT; переименование не меняет операции/суммы.
- `deleteCategory`: `{id:UUID,expectedRevision:int}` → `{id:UUID,deleted:true}`; native атомарно ставит categoryId=null всем связанным операциям, повышает их revision, не меняет ID/amount/date; категория более не предлагается.
- `saveSources`: `{packages:string[]}` → `{sources:string[]}`; set уникальных выбранных launcher packageName, max1000; native проверяет доступность пакетов, listener использует актуальный allowlist до чтения текста.
- `reviewCandidate`: `{id:UUID,expectedRevision:int,decision:"post",transaction:{kind,date,amount,currency,categoryId:null|UUID,note:string},confirmDistinct:boolean}` → `{candidate:Import,record:Transaction}`; новая запись только после native валидации; possibleMatchIds непустой требует confirmDistinct=true.
- `reviewCandidate`: `{id:UUID,expectedRevision:int,decision:"link",transactionId:UUID}` → `{candidate:Import,record:Transaction}`; связывает источник с существующей неудалённой записью, не прибавляет сумму. Нет автоматической перезаписи её полей/ручных правок.
- `reviewCandidate`: `{id:UUID,expectedRevision:int,decision:"ignore"}` → `{candidate:Import,record:null}`; источник помечен проигнорированным и не проводится повторно. Уже решённый/stale кандидат даёт CONFLICT, UI перечитывает state.
- `scanCamera`, `scanGallery`, `openNotificationAccess`: `{}` → `{jobId:UUID,status:"queued"}`; native генерирует jobId до main-thread dispatch. JSON не принимает URI/path/model/language/URL/callback.

## Java-межмодульный API

`storage.StorageApi`: `JSONObject state(String month,String currency)`; `JSONObject execute(String action,JSONObject payload)`; `JSONObject ingestCandidate(JSONObject source,ImportCandidate candidate)`. Возвращается data object БЕЗ bridge-envelope; ошибки через core.ContractException.
`storage.LedgerStore implements StorageApi`: `public static LedgerStore get(Context context)` — application-context singleton. MainActivity/service используют этот API; execute принимает только DB actions из whitelist, не scan/open/state.
`core.ContractException extends RuntimeException`: `public final String code,field`; constructor `(String code,String field,String safeMessage)`; field может null, getMessage безопасен. AppBridge ловит его, неизвестный RuntimeException → INTERNAL без текста исключения.
`core.ImportCandidate`: `public JSONObject toJson()`; `public static ImportCandidate fromJson(JSONObject value)`. JSON содержит ровно `{kind,amount,currency,date,dateOrigin,note,reasons,confidence,paymentReference}`; nullable поля как Import, unknown kind=null. paymentReference `string|null`: raw строка допустима только transient в результате parser, при storage ingress значение строго null.
`core.BankMessageParser`: `public static ImportCandidate parse(String text,long postTimeMillis,String zoneId,boolean allowPostTimeDate)`; `core.ReceiptParser`: `public static ImportCandidate parse(String text)`. Без БД/Android; источник/первичная валюта не угадываются.
`source` в ingestCandidate: `{kind,eventId,sourceKeyToken,revisionToken,accountSurrogate,paymentRefToken,packageName,label,capturedAt,postTime}`; kind `notification|receipt`, eventId UUID и revisionToken nonnull HMAC string обязательны; sourceKeyToken/accountSurrogate/paymentRefToken nullable HMAC strings, postTime nullable epoch-millis integer, packageName nullable, capturedAt UTC ISO8601.
ARC5-01: native превращает transient parser paymentReference в source.paymentRefToken, затем ставит candidate JSON `paymentReference:null` (ключ НЕ удаляется) и восстанавливает typed ImportCandidate через fromJson перед ingestCandidate. Storage запрещает nonnull raw paymentReference и сохраняет только разрешённые структурированные поля, не весь toJson blob.
Native sourceKeyToken/revisionToken HMAC создаёт до persistence. Receipt sourceKeyToken — scoped HMAC изображения; notification sourceKeyToken включает package/profile/key/tag/lifecycle, revisionToken — postTime+полезное содержимое. Если source identity не доказана, native создаёт устойчивый token конкретного observation и ставит candidate reason IDENTITY_UNCERTAIN; token не объявляется bank identity.
`ingestCandidate` → `{outcome:"posted"|"review"|"linked"|"duplicate"|"ignored",candidate:Import,record:Transaction|null}`. Отсутствие eventId/revisionToken — VALIDATION; неопределённая финансовая identity при валидном observation token → review с IDENTITY_UNCERTAIN, сохраняет кандидат и блокирует автопост.
Store создаёт/читает candidate/native IDs, проверяет Money/date/категорию, выполняет candidate+source link+transaction+dedup indexes одним SQLite commit; при exact replay возвращает прежний результат без новой суммы.

## Автоматический ввод и идентичность

Native принимает только выбранные package/profile до title/text/extras; postTime/key/tag не bank transaction ID. Сохраняются HMAC-SHA256 purpose+namespace+length-prefixed fields, per-install Keystore key; raw key/tag/account/reference/номер карты не сохраняются даже в таблице raw→surrogate.
Generic parser — осторожный fallback для явных завершённых income/expense; «все банки» — цель охвата, а не прошедшая совместимость. Unknown/перевод/возврат/pending/отмена/скрытая сумма/несколько сумм → needs_review с причиной, не нулевой/угаданный расход.
Автопост только при high и однозначных kind/positive amount/currency/date/источнике, известных scale и безопасной идентичности без нерешённого possible match. Категория по умолчанию null; после ручной правки повтор OCR/parser не перезаписывает её.
ReceiptParser выбирает final paid total покупки; receipt confidence=high требует явного однозначного completed-paid evidence, связанного с итогом. Bare «итог»/«к оплате» либо «наличными»+«сдача» без подтверждения оплаты не дают autoexpense: извлечённые структурированные amount/date и прочие известные поля сохраняются needs_review. Поддержанные ru/en/kz варианты paid evidence проверяются по фактическому коду/корпусу, поддержка всех настоящих чеков не обещается.
Неоднозначные separator `1,234`/`1.234` без проверенного шаблона, несколько итогов/платежей, неясная валюта/дата → review; сдача/переданные наличные/позиции плюс total не становятся расходом. QR/URL из чека не исполняется.
Exact revisionToken повторно идемпотентен, включая restart; новый payload/postTime/reused OS id даёт отдельное наблюдение, не вечное подавление по key. После разрыва lifecycle/потери ключа неопределённость → review. Notification removal не удаляет ledger.
Надёжный paymentRefToken в одинаковом provider/account/reference namespace связывает источники одной записи; receipt fiscal ID не равен bank ID. Противоречивые поля → review, без автоперезаписи существующей операции.
Одинаковые сумма+близкое время только possibleMatch, не identity. При пересечении receipt/notification и неясной самостоятельности новой покупки хранится needs_review с possibleMatchIds; второй расход не постится до link либо явного confirmDistinct. Две покупки не сливаются по одной сумме.
SQLite хранит настройку/категории/операции/кандидаты/источники/токены/связи; значения money TEXT, ссылочная целостность, revision CAS, soft-delete tombstones и дедуп-уникальность в DB. category deletion и итоги не создают второй независимый баланс.

## Jobs, OCR и UI

`Job={jobId,type,status,error}`; type `scanCamera|scanGallery|openNotificationAccess`, status `queued|running|completed|cancelled|failed`, error null либо envelope Error. Jobs — runtime status; после гибели процесса незавершённый OCR не объявляется completed, сохранённый Import остаётся в SQLite.
Одновременно максимум один media/OCR job; второй → BUSY. Cancel picker/camera → cancelled, без операции; нет обработчика камеры → ACTIVITY_UNAVAILABLE; permission denial → PERMISSION_DENIED. Возврат из notification settings перечитывает реальный notificationAccess, не считает его выданным автоматически.
OCR инициализирует реальный Tess4Android single worker, APK eng/rus/kaz models → private tessdata; no network/model name от JS. native ocr.ready=true только после успешной init; модель отсутствует/сломана → OCR_UNAVAILABLE, без fake распознанного чека.
Технические image guards: ≤20MiB bytes с ограничением чтения, decoded bounds ≤32000000 pixels, decode downsample до long edge≤4096; MIME image/* и успешное реальное декодирование обязательны. OCR text≤200000 chars, notification text≤65536 chars; превышение не обрезать в автопост, LIMIT_EXCEEDED/review.
Raw notification/OCR — только transient, raw title/text/image/URI не идёт в JS/state/logcat. Private temporary media очищается после обработки/cancel, максимум24ч с startup cleanup; фото пользователя не удаляется. После очистки raw reparse не обещается, Import исправляется структурированными полями.
Native после commit/job/status/resume исполняет только фиксированное `window.NativeEvents&&window.NativeEvents.onRefresh()`; никаких raw значений/имён JS-функций из источника. UI затем делает state; если страница не готова, onResume/первый state читает сохранённый результат.
`bridge.js` экспортирует `window.NativeBridge.request(action,payload):Promise<data>`; rejection имеет code/message/field. Он JSON.stringify/parse envelope, выбирает AndroidApp либо явный browser-preview adapter; raw envelope не передаёт view.
`view.js` экспортирует `window.AppView.render(state,ui)` и `toast(message,kind)`; ui `{tab:"records"|"categories"|"imports"|"settings",editTransaction:null|UUID,editCategory:null|UUID,reviewCandidate:null|UUID,busy:boolean,error:null|Error}`. UI-01: records включает monthly overview, categories — отдельная страница; app.js владеет ui/событиями/dirty drafts, view не вызывает native.
View формы: `data-form="transaction|category|settings|sources|review"`, input name соответствует payload полям; `data-id` — UUID/null edit target. App делегирует submit, serializes named fields и сохраняет dirty values/selection до render; refresh не затирает незавершённую форму, conflict показывается пользователю.
Кнопки с `data-action="newExpense|newIncome|editTransaction|deleteTransaction|newCategory|editCategory|deleteCategory|reviewCandidate|scanCamera|scanGallery|openNotificationAccess|changeTab"`, `data-id` при объекте, `data-tab` при changeTab; mutation/delete требуют явного submit/подтверждения UI.
index загружает внешние scripts в порядке `preview-adapter.js`, `bridge.js`, `view.js`, `app.js`; preview-adapter экспортирует `window.PreviewAdapter.request`, работает только при отсутствии AndroidApp, помечает browser preview, не симулирует OCR/notification успех и не подменяет APK demo данными.

## Ошибки, WebView и доказательства

Error codes: `BAD_JSON`, `UNKNOWN_ACTION`, `VALIDATION`, `SETUP_REQUIRED`, `CURRENCY_UNKNOWN`, `MONEY_INVALID`, `MONEY_SCALE`, `LIMIT_EXCEEDED`, `DATE_INVALID`, `NOT_FOUND`, `REFERENCE_CONFLICT`, `CONFLICT`, `STORAGE_FAILED`, `BUSY`, `PERMISSION_DENIED`, `ACTIVITY_UNAVAILABLE`, `OCR_UNAVAILABLE`, `IMAGE_INVALID`, `UNAVAILABLE`, `INTERNAL`. reasons дополнительно: `UNKNOWN_KIND`, `AMOUNT_MISSING`, `CURRENCY_MISSING`, `DATE_MISSING`, `AMBIGUOUS_TOTAL`, `AMBIGUOUS_SEPARATOR`, `UNSUPPORTED_EVENT`, `POSSIBLE_DUPLICATE`, `IDENTITY_UNCERTAIN`, `LOW_CONFIDENCE`.
Фиксированный URL `https://appassets.androidplatform.net/www/index.html`; только GET и exact assets `/www/index.html`, `/www/styles.css`, `/www/view.js`, `/www/bridge.js`, `/www/app.js`, `/www/preview-adapter.js`; любое другое scheme/host/port/path/userinfo/method → непустой deny-response, без network fallback.
No INTERNET; blockNetworkLoads, no file/content/universal access, frames/popups/external navigation/SSL bypass; CSP запрещает external/inline scripts, connect/frame/object/base/form-action. Данные только textContent/DOM properties. Полные native границы и backup exclusions — SECURITY-REVIEW.md.
Просмотрены официальные [Currency/defaultFractionDigits](https://developer.android.com/reference/java/util/Currency#getDefaultFractionDigits()) и [Tesseract4Android](https://github.com/adaptech-cz/Tesseract4Android) 2026-11-02; версии сборки — назначение root, нативные испытания не заявляются.
