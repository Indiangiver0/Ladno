# APP-013: implementation security review v1

2026-11-04. security-engineer → architecture-lead. Версия приложения 0.3.0/code3; контракт `20982166…`. Проверены реальные исходники и отчёт исполнителя v2. Это code inspection, не приёмка приложения и не устройство/QA.

**Вывод:** в прочитанном QR-пути подтверждённых P0/P1 и новых сетевых/банковских полномочий не найдено. Передать главе и независимому QA с сохранением ограничения повреждённого соседнего QR. Финальная сборка/Gradle и runtime в этом review не запускались и не ожидаются.

- URI: `FiscalQrParser.java:47–95` проверяет UTF-8≤4096 bytes, управляющие символы/backslash, scheme, exact authority/host, raw path, userinfo/port/fragment, ровно четыре однократно decoded query-параметра и duplicates после decode. Нет загрузки URL. `s` проходит строгую положительную decimal-грамматику и Money, `t` — STRICT календарный разбор; только KZT/scale2. `:109–111` возвращает unknown kind/uncertain без payment reference.
- Изображения: `ReceiptQrScanner.java:18–49` ограничивает файл 20МиБ, источник 32млн пикселей, sampling до стороны4096/8млн decode pixels; Bitmap освобождается до luminance allocation. EXIF orientation применяется в `:52–71`. `ReceiptQrDecoder.java:31–62` повторно проверяет размеры/длину RGB, ограничивает detected QR≤16, текст≤4096 bytes, запрещает structured append; смешанные distinct/invalid decoded payloads отвергает `FiscalQrParser.select:26–44`. Эти guards прочитаны, их Android memory/performance поведение на устройстве не измерялось.
- Поток: `NativeRuntime.java:238–280` запускает QR первым; полученный Result идёт без OCR, отсутствие decoded результата ведёт в прежний OCR. Invalid/unknown/multiple QR дают ContractException до `store.ingestCandidate`; сообщения QR фиксированы. Raw text/URI не попадают в DTO/JS/логи/SQLite: наружу идут canonical amount/date и opaque tokens; `:284–292` очищает note/paymentReference. Выбранное изображение временно копируется в private cache и удаляется в finally; cleanup24ч предусмотрен в `:313–378`. Это ограниченное временное хранение изображения, а не обещание его отсутствия на диске.
- Идентичность: `NativeRuntime.java:251–270` HMAC получает validated locator и normalized revision с разными purpose в `receipt-fiscal-qr-v1`, банковские account/payment tokens=null. `SourceTokens.java:32–79` использует AndroidKeyStore HmacSHA256, length-prefixed поля и fail-closed при отсутствии ключа; plaintext fallback в прочитанном коде нет. `LedgerStore.java:336–343` ищет exact observation; kind=null/review не доказывает платёж и не даёт автоматического расхода. SQLite dedup после restart/ignore/edit этим review не исполнялся.
- Полномочия: main manifest не содержит INTERNET или accessibility service, `usesCleartextTraffic=false`; build.gradle фиксирует ZXing core3.5.3. Поиск `rg` по main Java/manifest не нашёл HTTP client/URL loading в QR-пути, вывода raw или нового bank UI API; единственный найденный `loadUrl` — существующая фиксированная страница MainActivity. Сетевой adapter/stub не добавлен.

**IS13-01 / P2 / известное ограничение, не исправлено:** MultiDetector может не обнаружить повреждённый соседний QR. Guard `ReceiptQrDecoder:59–61` видит только detected symbols; если сосед не обнаружен, читаемый QR может быть выбран, а при отсутствии всех decoded QR запускается OCR. Поэтому нельзя обещать отказ при каждом визуально присутствующем втором QR. `ReceiptQrDecoderTest.java:65–74` сохраняет исходную фикстуру/assertion под явным `@Ignore`; это один skipped diagnostic, не PASS и не исправленный counterexample. Первый FAIL описан отчётом исполнителя; его runtime здесь не воспроизводился. Решение о достаточности такого decoded-only ограничения принадлежит главе/QA/суду, а не этому исполнителю.

Проверки: обязательные профиль/AGENTS/PROTOCOL прочитаны целиком; `Get-Content`/нумерация строк и `rg` по указанным исходникам выполнены; `Get-FileHash -Algorithm SHA256` выполнен. Никаких новых источников/API, телефона, ADB, банковских экранов, реальных чеков, полного Gradle или изменений продукта. Изменён только этот новый отчёт. Следующее действие — независимая проверка точной версии и диагностического ограничения, без заявления об автоматическом OFD API.
