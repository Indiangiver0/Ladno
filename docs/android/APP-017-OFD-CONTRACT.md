## Request: точный adapter boundary

Provider `kazakhtelecom-consumer-v1`: **HTTPS443 `consumer.oofd.kz`, exact path `/api/consumer-proxy/api/tickets/get-by-url`, GET**, query ровно `f,i,s,t`, body отсутствует; header `Content-Type: application/json`, Accept JSON. URL полностью строится native из validated полей, raw QR URL не fetch-ится. JS не получает URL и не задаёт host/path/headers. Нет банковских credentials, WebView cookies или альтернативного endpoint.

`i` — ФП, `f` — РНМ: строки ASCII digits с сохранением нулей, технический subset 1..32 цифры. `s` — положительная decimal сумма, ≤24 цифр целой части и ≤2 дробных, без знака/экспоненты/группировки. Перед запросом canonical scale2. `t` — строгая реальная `yyyyMMdd'T'HHmmss`. Семантика `i/f/s/t`, тенге/тиын: [опубликованный КГД формат, п.98.2](https://www.gov.kz/org/kgd/documents/details/59860?lang=kk); это источник известного формата, не утверждение актуальности старого закона. Currency KZT/scale2 дополнительно соответствует официальному renderer ₸, а не primaryCurrency/локали.

Classifier принимает только назначенный fiscal host/path и известную query grammar: без userinfo/явных портов/fragment/поддоменных суффиксов/неизвестных или повторных keys, control chars и повторного percent decode. Bare/legacy HTTP QR, если поддержан локальным decoder, никогда не вызывает HTTP: endpoint всегда fixed HTTPS. Несколько разных fiscal QR требуют выбора, payment/POS QR не становится fiscal locator. В production query не подставляются developer samples.

## Success schema и typed поля

HTTP200 JSON **непосредственно root object**, без придуманного `success`/`data` wrapper. Наблюдаемая обязательная для нашего adapter структура:

- Root `ticket:Object`, `kkmFnsId:String`; root также содержит `ticketDescription`, seller/location fields, `foundDate`, `taxes`, `totalDiscount`, `totalMarkup`, `measureUnits`. Для candidate эти лишние поля игнорируются.
- `ticket.type:String` = `TICKET`; `fiscalId:String` nonempty; `offlineFiscalId:null`; `cancelDate:null`; `transactionDate:String`; `totalSum:Number`; `operationType:Number` (integer); `payments:Array`; `items:Array`. Missing/wrong required type не превращается в ноль/null success.
- `payments[]` содержит `paymentType:String`, `sum:Number`; оба образца `CARD`, exact payment sum = exact `totalSum`. Официальный renderer знает `CASH|CARD|MOBILE`; taken/change не expense total.
- `items[]`: `itemType:Number`; проверенный тип1 содержит `commodity:Object`, тип5 — `commodity:null` и `discount:Object` (реальная восьмая строка sample5). Нельзя требовать commodity object для каждой строки или объявлять discount товаром. Commodity содержит `name:String`, `quantity:Number`, `price:Number`, `sum:Number`, `measureUnitCode:String`, taxes и дополнительные fields; modifiers/options/discount/markup могут быть nullable. Позиции и discount bounded transient, не расширяют существующий ImportCandidate/SQLite. Quantity — точный decimal, не money scale2. Неизвестный itemType не получает default high. Итог берётся из `totalSum` после скидок, не из пересчитанных товаров/налогов/переданных наличных; sample5 net total остаётся `3547.00`.
- `acceptedAt` наблюдался String или null даже для того же чека при повторном GET; `kkmId` также может меняться String/null. Их нельзя делать обязательным fiscal evidence или включать в financial revision identity. `insertedAt` null. Metadata variability не создаёт новую операцию.
- Ответ содержит `payload`, `requestPayload`, `responsePayload` как raw String/null документы. **Не parse для candidate, не persist/log/JS.** Customer/seller/account/card/RRN/transaction IDs вне candidate тоже игнорируются. Error response schema не установлена, не придумывается.

Source enum `operationType`: **0=покупка, 1=возврат покупки, 2=продажа, 3=возврат продажи** с позиции кассы. Значение2 может стать expense покупателя; 0 не превращать автоматически в его income; 1/3/unknown/cancelled — review, без обычного расхода.

Money читается из JSON **исходным decimal lexeme**, без double/float/JS Number: lexical guard → BigDecimal scale2 с UNNECESSARY/BigInteger minor → canonical string. Whole token `4395` допустим как `4395.00`; `4395.000`, exponent, отрицательный/нулевой/overflow total отклоняются. Суммирование payments точное; конфликт currency или total → review/error. Не доверять source frontend `Number/toFixed` для денежных вычислений.

## Fiscal evidence, дата и state machine

`lookup → validate schema → validate receipt identity → normalize → dedup/storage`. Допуск expense/high требует одновременно: official HTTPS200 typed `TICKET`; numeric operationType2; присутствующих `cancelDate:null`, nonempty fiscalId и online identity (offlineFiscalId null для проверенного subset); **exact string fiscalId==QRi и kkmFnsId==QRf**; total==QRs; source KZT; transactionDate==QRt по локальным календарным компонентам; известных payment types и exact sum(payments.sum)==total; отсутствие остальных противоречий/unknown status; existing identity/dedup gates. Это evidence уже зарегистрированного fiscal SALE из consumer lookup, не придуманный `status=PAID`. Новый status/shape/непроверенный offline receipt не получает default high.

Samples4/5 QR локально кодируют `2026-11-03T20:08:21`/`2026-11-03T20:02:38`; API — те же значения с `.000`; strict match=true. Нормализация разрешает только нулевую fractional part, не добавляет offset/+2h. На бумаге root видит22:08/22:02 — разница display time не объяснена, timezone не выдумывается. Ledger date — согласованная source LocalDate `2026-11-03`, capturedAt не заменяет её. Ненулевые fractions/offset/неизвестный timestamp format требуют отдельного parser contract. При несовпадении QR/API или конфликте календарной даты с явно распознанной бумагой, особенно через полночь, review без автоматического сдвига даты. Известный конфликт OCR fields не скрывать.

Validated result использует существующий `ImportCandidate={kind,amount,currency,date,dateOrigin,note,reasons,confidence,paymentReference:null}`; source dateOrigin. Финальное policy решение high/expense только через existing storage gates; partial/local-only candidate — uncertain/review, без guessed kind. Не добавлять raw response/items в DTO. Сетевая ошибка не создаёт пустую карточку; при полезных local QR данных оставить один review candidate и объяснение недоступности проверки.

`source.kind=receipt`, UUID eventId и purpose-scoped HMAC tokens. Для offline и online одного QR сохраняется **буквально существующая пара 0.3.0**: `sourceKeyToken=HMAC("receipt-source","receipt-fiscal-qr-v1",qr.locator())` и `revisionToken=HMAC("receipt-revision","receipt-fiscal-qr-v1",qr.locator(),qr.revision())`; `qr.locator()` — host/ФП/РНМ, `qr.revision()` — canonical amount/source timestamp. Вместе пара уже включает полный наблюдаемый locator и сумму; одну пару РНМ/ФП не объявлять уникальной навсегда. KZT определяется подтверждённым форматом. **Не вводить отдельные API namespace/financial revision:** API type/confidence/items, metadata, raw JSON, acceptedAt/kkmId и transport не меняют ни один токен. API-first high идёт через существующие storage gates. Fallback-first поздний success с той же парой возвращает существующий review/ignored/posted/linked без нового кандидата, повышения pending или перезаписи пользовательских правок; автоматическое обогащение pending требует отдельного atomic storage контракта. Таким образом OFDSEC-01 закрывается в дизайне без изменения LedgerStore; runtime replay/ignore/edit/restart ещё проверяет QA. Fiscal locator не bank paymentReference. Receipt/notification/POS без доказанной общей bank identity — possible-match review/link, без удвоения. Отдельный POS490 соответствует fiscal490, не пятый расход. Не сливать разные покупки по одинаковой сумме.

## Network/privacy и минимальные проверки

Native-only fixed client: стандартная TLS hostname/certificate validation, no redirects/arbitrary fetch/scripts/HTML rendering/cookies import/credential reuse. WebView остаётся offline. Connect5s/total10s с cancellation и закрытием body; compressed/decompressed body≤256KiB, JSON depth≤16, items≤500, transient item name≤512UTF-8bytes. Это наши защитные limits. Unexpected content type/schema, auth/CAPTCHA/429/5xx, mismatch, size/depth/time limit → безопасная ошибка, без retry loop/обхода/fake success. No response body/URL query/исключений с raw URL в logs, telemetry, JS или error text. Raw research только private `.local/app017/provider-*`, не tests/dist/APK; production raw transient и очищается.

Будущая QA: positive money/date/type/identity; non-sale0/1/3/unknown/cancel/missing-null guards; identity/total/date mismatches; fractional/large/exponent tokens; discounts/net total; QR+POS+notification dedup, повтор/ignore/edit; metadata changes; redirects/auth/HTML/oversize/timeout; no raw leakage. Synthetic fixtures обезличиваются и помечаются производными от actual schema. Успешный HTTP research не заменяет эти product tests.
