# APP-008 — расходы по категориям

Версия 1, 2026-11-03. Автор: calculation-analyst; передача finance-lead на проверку. Это спецификация, не свидетельство запуска приложения. Денежные правила `MONEY.md` сохраняют силу.

## Входы и состав расходов

- Источник — один согласованный `state` из `CONTRACT.md`: `selection.month`, `selection.currency`, `summary.scale`, `records`, `categories`, `summary.expense`. До настройки валюты график не вычисляется.
- `records` уже содержит только неудалённые сохранённые операции выбранных месяца и валюты. В разрез входят только `kind="expense"`; доходы и кандидаты `needs_review` не входят. `posted`/`linked` — статусы импорта, а не дополнительные расходы: учитывать только соответствующую единственную запись `records`.
- Период — календарный месяц по сохранённому `date`, без нового перевода даты через часовой пояс; границы месяца и валюта соответствуют `MONEY.md`. Не смешивать валюты и scale. Одинаковый ID записи дважды, неканоническая сумма, несовпадающие дата/валюта/scale или неизвестная ненулевая категория — ошибка согласованности, а не основание показать частичный разрез.
- Ключ группы — `categoryId`, а не название. `null` даёт «Без категории», участвует в полном расходе. Удалённая категория уже переводит записи в `null` в native. Разные ID с одинаковыми названиями остаются разными группами; подпись должна позволять их различить.
- Для стабильной сортировки UUID сравнивать лексикографически по ASCII; внутренний ключ `null` — `~uncategorized`, искусственного сектора «Остальные» — `~other`. Эти ключи не записываются как ID категории.

## Точные суммы

Для canonical строки `amount` со scale `s` удалить единственную десятичную точку (при `s=0` её нет) и прочитать полученную строку как целое `minor > 0`. Единица minor — `10^(-s)` единицы выбранной валюты.

`V[g] = сумма minor всех расходов группы g`; `T = сумма V[g]`.

Все суммы, сравнения и произведения для отношений выполняются в `BigInt` либо эквивалентной точной арифметике десятичных строк. Запрещены `Number(amount)`, `parseFloat`, арифметика double и ограничение агрегата 24 цифрами. Для вывода восстановить ровно `s` дробных знаков из целого; показать код валюты.

Проверка согласованности: `T` точно равен `summary.expense`, прочитанному как minor с тем же `s`. Несовпадение, ошибка ресурсов или отсутствие поддержки точной арифметики дают явное «Не удалось построить график»; запрещено подменять результат нулём или float. При неподдерживаемом `BigInt` остальные функции приложения должны оставаться доступны: не применять BigInt-литералы, способные сломать разбор всего скрипта.

## Проценты и порядок

Процент — только представление доли, суммы не округляются. Для `T > 0` и каждой исходной положительной группы:

1. `q[g] = (10000 * V[g]) div T`, `r[g] = (10000 * V[g]) mod T`.
2. `L = 10000 - сумма q[g]`. Выдать по одному дополнительному пункту первым `L` группам в порядке `r` по убыванию, при равенстве — по ключу ASCII по возрастанию. Каждая группа получает не более одного такого пункта.
3. `bps[g] = q[g] + выданный пункт`; один пункт равен `0,01%`. Печатать `bps div 100`, запятую и ровно две цифры `bps mod 100`. Сумма численных процентов исходных групп равна `100,00%`.

Это метод наибольших остатков, а не независимое HALF_UP для каждой категории. Погрешность представления одной доли меньше одного пункта; распределение воспроизводимо и не зависит от порядка входных записей или локали устройства.

Легенда сортируется по точному `V` по убыванию, при равенстве — по ключу ASCII по возрастанию. Для положительного расхода с `bps=0` показывать `0,00%` и пояснение «менее 0,01%». Расход и его точная сумма остаются видимыми.

## Круговая диаграмма и доступность

- Отдельная кнопка «Графики» открывает экран с явными месяцем и валютой. В круге не более шести секторов. При 1..6 положительных группах — каждая отдельно; при >6 — первые пять из указанной сортировки и один сектор «Остальные» с суммой всех оставшихся. Полная легенда содержит все исходные группы с точными суммами и процентами.
- Проценты считаются один раз по исходным группам. `bps[Остальные]` равен сумме их `bps`, а не новому округлению сгруппированных сумм. Таким образом проценты круга и подробной легенды согласованы.
- Геометрия строится по точным суммам секторов, не по округлённым процентам. Пусть `C[j]` — накопленная сумма первых `j` секторов, `C[0]=0`, `C[n]=T`; `U=1000000000`. Граница `p[j]=(U*C[j]) div T`, от `0` до `U`. Только полученное ограниченное целое можно перевести в `Number`; угол равен `2π*p[j]/U`. Последняя граница точно `U` (полный круг). Погрешность границы от этой дискретизации меньше `1/U` оборота.
- Один сектор отображается полным кругом; не полагаться на SVG-дугу с совпавшими началом и концом. Очень маленький положительный сектор может иметь нулевую ширину при выбранной геометрической дискретизации. Не назначать фиктивный минимальный угол: легенда сохраняет его сумму и поясняет, что малая доля может быть неразличима на круге.
- Цвет не единственный способ чтения: названия, точные суммы и проценты доступны текстом, сектор «Остальные» объяснён. Если доступность/платформа не позволяют отрисовать круг, точная легенда должна оставаться доступной.
- При `T=0` не делить и не рисовать полный/пустой сектор как финансовый результат: «За этот месяц расходов нет», сумма `0` с ровно `s` знаками и валюта, действие добавления расхода. До настройки отличать отсутствие валюты от нулевого расхода.

## Контрольные примеры

- KZT, scale2: категория A `0.10`, категория B `0.20` → `T=0.30`, `bps A=3333`, `bps B=6667`, суммы `0,10` и `0,20`; геометрия `p=[0,666666666,1000000000]` для порядка B,A.
- Три равные группы с ключами A,B,C: `bps=[3334,3333,3333]`, порядок A,B,C; границы `0,333333333,666666666,1000000000`.
- Семь равных групп A..G: проценты A..D `14,29%`, E..G `14,28%`. Круг A..E и «Остальные» (F+G): `28,56%`; пересчёт процентов шести секторов отдельно запрещён.
- Два расхода по `999999999999999999999999.99` → `T=1999999999999999999999999.98`, доли `50,00%` каждая; агрегат не обрезать. Отдельные USD или иной месяц не участвуют.
- Расход с `null` и расход с обычной категорией входят в `T`; назначение или удаление категории меняет только разрез. Доход любой суммы и непроведённый чек не меняют `T`.

Независимые эталоны специалиста — `APP-008-CHART-FIXTURES.json`; согласованность и реализацию проверяют глава и отдельный QA. Внешние ставки, налоги, обмен валют и юридические правила для этого разреза не требуются.
