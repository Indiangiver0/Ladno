# APP-004-PERMISSIONS v1 — доступ и данные автоматического ввода

Дата просмотра первичных источников: 2026-11-02. Автор: security-engineer; проверяющий: architecture-lead. Статус: архитектурное предложение, без реализации и самостоятельной приёмки.
Входы: APP-004, AGENTS.md, team/PROTOCOL.md, профиль security-engineer; контракты и OCR — [AUTO-ENTRY.md](AUTO-ENTRY.md). Подтверждены Android и желаемые «все банки»; push/SMS, устройства, страна, валюты и язык чеков пока не уточнены.

## Уведомления: фактическая граница Android

- `NotificationListenerService` (API18+) получает опубликованные/обновлённые уведомления. Сервис объявляется с `BIND_NOTIFICATION_LISTENER_SERVICE`; это защита привязки сервиса, а не обычный runtime-запрос пользователя. [Android API](https://developer.android.com/reference/android/service/notification/NotificationListenerService).
- Пользователь отдельно выдаёт/отзывает notification access в системных настройках listener; переход в настройки ещё не означает выдачу доступа. Проверять фактическое разрешение и подключение сервиса, обрабатывать отсутствие соответствующего экрана. [Settings API](https://developer.android.com/reference/android/provider/Settings#ACTION_NOTIFICATION_LISTENER_DETAIL_SETTINGS).
- `POST_NOTIFICATIONS` на Android13+ разрешает показывать собственные уведомления приложения; он не разрешает читать уведомления банков и не заменяет notification access. [Android Developers](https://developer.android.com/develop/ui/compose/notifications/notification-permission).
- Системный доступ listener может охватывать уведомления других приложений, включая личные сообщения. Нельзя описывать его как системное разрешение «только выбранные банки»: выбор банков ограничивает последующую обработку нашим приложением. [Android15 CDD §3.8.3.2](https://source.android.com/docs/compatibility/15/android-15-cdd#3_8_3_notifications).
- После системного доступа сначала проверять package/profile по локальному списку выбранных источников; у остальных не извлекать text/extras, не сохранять и не логировать содержимое. У выбранного источника разбирать только необходимые поля. Проверка package из системных метаданных предпочтительнее имени/иконки/текста «Банк»; она не доказывает истинность операции.
- Listener работает после `onListenerConnected`; low-RAM Android10 и ниже не поддерживаются. В work profile listener игнорируется; DPC может закрыть уведомления рабочего профиля для личного listener. Нельзя обещать сбор из всех профилей/пользователей. [NLS API](https://developer.android.com/reference/android/service/notification/NotificationListenerService), [work profiles](https://developer.android.com/work/managed-profiles).
- На Android15 недоверенный listener не получает незаредактированное содержимое уведомления с обнаруженным OTP. Не обходить защиту и не обещать, что любая сумма останется доступной; это не утверждение, что Android скрывает все банковские уведомления. [Android15 OTP redaction](https://developer.android.com/about/versions/15/behavior-changes-all#otp-redaction).
- Установка APK из файла/через загрузку может требовать отдельного подтверждения Restricted Settings перед notification access; Android15 CDD явно включает listener. Это отдельный барьер от разрешения установки и самого доступа. Конкретный путь зависит от ОС/способа установки; настройки сейчас не менялись. [CDD Restricted Settings](https://source.android.com/docs/compatibility/15/android-15-cdd#2_2_5_security_model), [Android Help](https://support.google.com/android/answer/12623953?hl=en).
- `getActiveNotifications()` даёт текущие неудалённые уведомления после подключения, не банковский архив. Пропущенное/неопубликованное/уже удалённое событие, скрытый текст или отсутствие суммы нельзя восстановить догадкой. Отзыв доступа/разрыв подключения показывать как недоступность сбора; полноту учёта не заявлять. [NLS API](https://developer.android.com/reference/android/service/notification/NotificationListenerService#getActiveNotifications()).
- «Все банки» — цель покрытия адаптерами, не доказанная совместимость каждого банка, версии, языка и шаблона. Неизвестный/неполный источник передаётся в проверку/ручной ввод по AUTO-ENTRY.md; отсутствие уведомления не означает отсутствие операции.

## SMS: отдельное решение

- Опубликованное уведомление SMS-приложения может попасть в listener при доступе к этому источнику; это только показанное содержимое, без чтения inbox/старых SMS. Добавление SMS-приложения расширяет обработку на его уведомления и требует явного выбора этого источника; текст отправителя также недоверенный.
- Прямое чтение SMS-хранилища/получение SMS через `READ_SMS`/`RECEIVE_SMS` — отдельный, пока неподтверждённый scope. Оба разрешения dangerous и hard restricted, требуют allowlist установщика; одного согласия на notification access недостаточно. Не запрашивать их в предлагаемом notification-пути. [Manifest permissions](https://developer.android.com/reference/android/Manifest.permission#READ_SMS), [RECEIVE_SMS](https://developer.android.com/reference/android/Manifest.permission#RECEIVE_SMS).

## Чеки: доступ по действию пользователя

- Для существующего изображения предложен системный Photo Picker: доступ только к выбранному медиа, без широкого runtime-разрешения на всю галерею. При недоступности предусмотрен `ACTION_OPEN_DOCUMENT`; отмена не создаёт расход. Доступ к URI временный; длительный доступ не получать без необходимости. Picker может предлагать облачное медиа выбранного пользователем провайдера — нельзя называть любой выбор гарантированно офлайн. [Photo Picker](https://developer.android.com/training/data-storage/shared/photo-picker), [минимизация разрешений](https://developer.android.com/privacy-and-security/minimize-permission-requests#open-media).
- Для снимка предложен вызов установленной камеры через `ACTION_IMAGE_CAPTURE`, без собственного `CAMERA`; при встроенной камере потребуется отдельный runtime `CAMERA` непосредственно перед съёмкой. Это альтернативы, стек/UX ещё не выбраны. Проверить отказ, отмену и отсутствие камеры. [Camera intent](https://developer.android.com/privacy-and-security/minimize-permission-requests#take-photo), [CAMERA API](https://developer.android.com/reference/android/Manifest.permission#CAMERA).
- Выбранный URI/картинка, OCR-текст и уведомление — недоверенный ввод: ограничить размеры файла/bitmap/строк и время обработки до декодирования/разбора; проверять формат и ошибки URI. Числовые пределы согласовать с реализацией и испытать; сейчас они не измерены. Ссылки/QR/notification actions не исполнять для получения недостающей суммы.

## Предлагаемая минимизация и срок хранения

- Предложение для личного MVP: распознавание и фильтрация локально, без передачи исходников/кандидатов в облако/телеметрию. Это не подтверждённое требование пользователя и не испытанная реализация. Для папы предложены отдельная установка и независимые данные; общий бюджет, аккаунт и синхронизация не подразумеваются.
- Notification raw: `title/text/extras` только в памяти после фильтра; `payloadRef` по умолчанию отсутствует, текст удалить после извлечения/отказа. OTP, PIN, пароли, полные номера карт/счетов, сообщения посторонних приложений не переносить в кандидата, evidence или диагностику; банковские учётные данные не нужны этому пути.
- Durable очередь содержит минимальные `RawSourceEvent`-метаданные и нормализованный кандидат: источник/профиль, key/postTime/lifecycle/revision, время получения, сумма/валюта/дата/тип и необходимые причины проверки; категория необязательна. `fieldEvidence` — имя поля/координаты/правило, без полного raw-сниппета. Нет данных → unavailable/review, не ноль и не валюта демо.
- Для сравнения повторов предложен keyed digest с областью установка+источник+профиль и версией ключа; ключ — в Android Keystore. Digest остаётся чувствительной метаданной, не считается анонимизацией и сам по себе не доказывает идентичность покупки. Утрата ключа/разрыв наблюдения → неопределённость, не подавление новой операции. [Keystore](https://developer.android.com/privacy-and-security/keystore).
- Receipt raw: временная копия только в private internal storage; предложение TTL ≤24ч либо раньше после обработки/отмены, с уборкой после перезапуска. Исходное фото пользователя не удалять. После удаления raw повторное распознавание/показ оригинала не обещается: ручная правка либо новый выбор изображения. TTL — решение для главы, не подтверждённый запрос пользователя. [Internal storage](https://developer.android.com/training/data-storage/app-specific#internal).
- Кандидаты/операции и минимальные связи происхождения сохраняются локально до удаления пользователем; удаление кандидата/источника убирает его ненужные временные копии и fingerprint. При повторном импорте удалённого источника полная память о дублях не гарантируется. Отзыв OS-доступа останавливает новый сбор, но сам не удаляет прежние операции; интерфейс должен различать эти действия.
- В логах/краш-отчётах/артефактах проверок — только код ошибки, этап и безопасный внутренний ID; без текста, изображения, URI, сумм, контрагентов, raw key/digest. Тестовый корпус синтетический/обезличенный; реальные уведомления и чеки в текущей работе не читались.
- Private storage не исключает Auto Backup: Android по умолчанию резервирует многие файлы/БД. Для предложенного локального режима исключить финансовые БД, очередь и исходники из cloud backup и переносов, проверить правила для целевых SDK/ОС; `allowBackup=false` отдельно не гарантирует отключение D2D на всех OEM. Потеря устройства без отдельного согласованного экспорта означает риск потери локального учёта. [Auto Backup](https://developer.android.com/identity/data/autobackup).

## Применимые риски и конкретные будущие проверки

Это сценарии риска, не подтверждённые дефекты отсутствующего Android-приложения; приоритеты P2 относятся к проектным неопределённостям.

- SEC-01 / P2: широкий OS-доступ захватывает личный текст → синтетические банковское/постороннее уведомления и поддельное отображаемое имя; ожидание: проходит только выбранный package/profile, постороннее не попадает в очередь/логи. Основание: широкий NLS-доступ выше.
- SEC-02 / P2: скрытая сумма/баланс/повтор/неизвестный шаблон создаёт неверную запись → тестировать неполный текст, OTP-redaction, отключение listener и обновление уведомления; ожидание: неизвестное не проводится догадкой, повторы обрабатываются по AUTO-ENTRY.md, UI не заявляет полноту.
- SEC-03 / P2: URI/огромная картинка/длинный текст ломает импорт → повреждённый файл, потерянный URI, отмена, превышения согласованных лимитов; ожидание: безопасная ошибка без расхода и без сохранения исходника в диагностике.
- SEC-04 / P2: чек/уведомление утекает через raw/log/backup → проверить TTL и уборку после crash/restart, содержимое private files/очереди/logcat/backup test archive; ожидание: нет запрещённых полей и удалённых raw, локальные финансовые файлы исключены из выбранных переносов.
- SEC-05 / P2: отзыв доступа ошибочно считается удалением/новый запуск читает старые чужие источники → revoke/regrant, смена allowlist, профиля и повторная установка на отдельном тестовом устройстве; ожидание: статус отражает реальный доступ, фильтр применяется до обработки, история не смешивается между установками.
