# APP-007: Google Play Protect блокирует установку

- Дата: 2026-11-03, Asia/Qyzylorda. Родитель APP-005. Статус: USB-установка выполнена, подтверждение пакета и пользовательский запуск отдельно; прежняя PlayProtect-блокировка интернет-установки не объявлена снятой.
- Пользователь: на телефоне не даёт установить APK; скриншот показывает Google Play Защита, «Приложение заблокировано для защиты устройства», предупреждение о доступе к деликатным данным/финансовом мошенничестве. За сообщением открыт мессенджер; точный путь установки/телефон/OS пользователем ещё не подтверждены.
- Проверяемый артефакт: прежний mainAPK38c9d4490419eda3685e7187281d5f1ecfb958a95d77c57f7f59633febcfbd5a, версия0.1.0/packagecom.ladno.finance. Сборка содержит настоящий NotificationListenerService. READ_SMS/RECEIVE_SMS/accessibility/INTERNET отсутствуют. APK на Android11AVD устанавливался, но AOSPAVD не моделирует GooglePlayProtect на телефоне.
- Цель: установить подтверждённую категорию блокировки, отделить факты от предположений и выбрать легитимную установку/распространение с сохранением нужной функции уведомлений. Не обещать, что re-sign/release сам по себе снимет блокировку, не удалять необходимую функцию без решения пользователя.
- Ответственный отдел: architecture/security; глава и один необходимый security specialist. Новые read-only findings в team/reports/APP-007-install-diagnosis.md; production/frozen215/старые reports не менять. Root владеет карточкой и оркестрацией, не выполняет действия с личным телефоном без выбора пользователя и его системных подтверждений.
- Источник: https://developers.google.com/android/play-protect/warning-dev-guidance?hl=en , секция App blocked to protect your device; точный текст соответствует скриншоту. Google описывает блокировку internet-sideloaded приложений с sensitive notification-listener/SMS/accessibility. Для данного APK это обоснованная гипотеза причины, не доступ к персональному classifier log и не подтверждение malware.
- Критерии: пояснение совпадает с официальной категорией; локальный manifest подтверждает NLS; варианты различают стандартный developer USB/ADB workflow, официальную проверку/распространение и отдельную сборку без NLS (только если выбрана). Ни один вариант не гарантирует прохождение PlayProtect без фактической проверки.
- Не выключать Play Protect/другие защиты, не удалять/маскировать permission ради уклонения от классификации, не публиковать/загружать APK и не подавать appeal без отдельной авторизации. Подготовка не означает отправку. Не читать личные уведомления/содержимое телефона для диагностики установки.

## Фактический следующий шаг

- Реальный глава `/root/install_architecture_lead` назначил одного `/root/install_architecture_lead/install_security` и отдельно проверил первичные Google/Android источники и manifest/APK. Отчёт APP-007-install-diagnosis.md31строка/SHA3d1c778ff787fe9429005b4db0af764188a3ee4681da6ec26cddc39ffb9c793c. Это диагностика, не новая готовая сборка/вердикт о безопасности.
- Пользователь явно выбрал возможность USB. Root сообщил, что доверие компьютеру/USB debugging подтверждает сам пользователь и PlayProtect остаётся включённой.
- `adb devices -l` с ANDROID_USER_HOME=локальныйкэш, exit0: список пуст. Ни одного телефона/эмулятора не выбрано; install/settings/grants/чтение личных данных не выполнялись. Ожидаются подключение кабелем, включённая отладка и подтверждение доверия на телефоне. При нескольких устройствах цель выбирает пользователь; без explicit target не устанавливать. Install-r сохраняет данные, uninstall/clear на личном телефоне не разрешены.
- После сообщения «он включен» повторныйADBсписокпуст. Read-only WindowsPnPпоказал StatusOK SAMSUNG Mobile USB Composite Device и Mobile USB Modem, но Android/ADB интерфейс не найден. Физический Samsungподключён; причина отсутствияADB пока не установлена (конкретныйtoggle/USBmode/driver/policy неизвестны). Не считать USBdebugging подтверждённым лишь включённымрежимомразработчика; rootпроситпроверитьименноUSBdebugging/phoneprompt. Защиты/драйверы/данныене менялись.

## Успешная установка после разрешённого USB-подключения

- Пользователь «делай»; ADB обнаружил единственный авторизованный физический Samsung SM-S921B, Android API36/arm64-v8a. Полный серийный номер намеренно не дублируется в репозитории. Перед install проверены SHAAPK38c9d4490419eda3685e7187281d5f1ecfb958a95d77c57f7f59633febcfbd5a и отсутствие прежнего пакета.
- Реальная команда с явно выбранным телефоном `adb -s <user-confirmed-device> install -r --no-incremental android-app/dist/ladno-0.1.0-debug.apk`: exit0, «Performing Streamed Install / Success». Это установка именноmainAPK, неandroidTestAPK.
- PlayProtect/прочиезащиты/драйверы не выключались и не перенастраивались. Не выполнялись uninstall/clear, чтение финансовых данных, автогрант NotificationListener, UI/input-команды или публикация. Успех developerUSBworkflow не доказывает снятие Googleклассификации/разрешение установки из мессенджера.
- Следующий пользовательский шаг: открыть «Ладно», выполнить setup и при желании выдать доступ через системный экран самому. Установка на физический телефон подтверждает installability этой версии на данном API/ABI, но сама по себе не доказывает работу полного UI/банков/камеры.
