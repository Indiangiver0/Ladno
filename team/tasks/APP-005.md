- Цель результата: реальный устанавливаемый APK и исходники, сохраняющие записи на телефоне. Не выдавать старый web-прототип/документы или непроверенный scaffold за приложение.

## Приёмка

- A1: собран APK, app identity/version/minSDK/совместимость указаны, проект воспроизводимо собирается; фактические команды и тесты сохранены. Установка/доступ к реальным уведомлениям на телефоне пользователя остаётся пользовательским действием, без чтения личных данных агентом.
- A2: доходы/расходы и категории создаются/редактируются/сохраняются в локальной БД между перезапусками. Новая установка пуста, synthetic demo не подменяет реальные записи. Категория null допустима, последующая категоризация не меняет денежный итог и не создаёт вторую запись.
- A3: реальный Android NotificationListenerService, включаемый пользователем, обрабатывает выбранные источники. Точное новое явное сообщение о завершённой операции с определёнными полями автоматически создаёт запись; неполное/неизвестное/сомнительное идёт на разбор с причиной. Не заявлять непроверенную совместимость каждого банка/версии; сумма, скрытая банком/ОС, не выдумывается.
- A4: камера/выбор изображения реально передаёт чек локальному OCR; оплаченный итог/дата/валюта распознаются и создают расход при достаточных однозначных данных, иначе открывается разбор с сохранённым результатом. Ошибка OCR/файла не создаёт нулевую/ложную операцию. Кириллица не обещается на неподдерживающей её модели.
- A5: точная денежная арифметика, валюта/scale/дата, повторы, receipt+notification и manual edit согласованы. Нет float денег, скрытого округления/агрегации валют/двойного расхода. Переводы/возвраты/неясное направление требуют разбора, пока не выбран явный тип учёта.
- A6: отдельные реальные специалисты/главы, независимый QA модели/сборки/доступных сценариев и суд по зафиксированной версии. Native/OCR/device/bank tests называются выполненными только по факту; ограничения APK-альфы явно сообщаются.

## Проектное направление для проверки архитектором

Один Android package с native Java-сервисами/SQLite/OCR и локальным WebView-интерфейсом на основе стиля предыдущего прототипа. Локальные доверенные assets/bridge, внешняя навигация/произвольные URL недопустимы. Выбор Java уменьшает сборочные зависимости; окончательный контракт и выбранные OCR/Gradle/SDK версии проверяются по официальным источникам до сборки. UI не должен быть просто старым demo без реального native-хранилища/доступа.

Деньги: положительный canonical decimal string+ISO currency+scale; внутри BigInteger/BigDecimal с UNNECESSARY для лишней точности. Пользователь явно выбирает основную валюту; явная валюта источника сохраняется отдельно, разные валюты не суммируются. Отчёты по выбранной календарной дате/месяцу, source timestamp отдельно; политика даты уведомления при отсутствии банковской даты должна быть явной. Внедряемые числовые/файловые лимиты описываются, не превращаются в финансовые правила.
