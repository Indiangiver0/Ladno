# APP-015: Freedom/Halyk уведомление есть, входящего нет

- Запрос/уточнение пользователя: уведомления Freedom и Halyk видны в Android-шторке, но в «Ладно» ничего не появляется. Не просто пустые поля review.
- Статус: needs_information, узкая диагностика реального capture/payload/result. Зависимость APP-014; ограниченная 0.3.0 позднее доставлена по APP-016.
- Ответственный отдел: backend-data, реальный повторный head `/root/import_backend_lead`, один отдельный read-only codebase специалист по его назначению. Root технически координирует.
- Критерии: проверить silent-drop gates/выбор источников/доступ/listener state по коду, запросить недостающие конфигурационные факты; не объявлять конкретный defect без подтверждения. Не пытаться получить отсутствующий Kaspi OS event этим путём.
- Пользователю задан pending вопрос о включённом доступе и выборе обоих banking apps в «Ладно → Настройки». Реальных payload/скриншота чека пока нет.
- Ownership главы ONLY `team/reports/APP-015-capture-triage.md`; специалист read-only. Код/подготовленный APK/QA reports пока не изменяются. Никаких bank extras/private data, автоматической выдачи доступа, других профилей, UI черезADB или settings mutations.
- Переход к исправлению — только по установленной причине/контракту с отдельным ownership, затем проверка головы/затронутого QA/суда. Диагностическое сообщение само по себе не приёмка приложения.

## Уточнения

- Реальный explorer `/root/import_backend_lead/capture_gate_explorer` завершил read-only исследование, глава отдельно проверил результат и сохранил APP-015-capture-triage.md. Подтверждены диагностические неоднозначности grant≠connected и review≠все исходы; причина конкретного телефона неизвестна, кода/телефона отдел не менял.
- Пользователь затем подтвердил: «Доступ включён, оба банка выбраны». Выбор/доступ по наблюдению пользователя подтверждён, точный OS binding/profile/package и новый event result ещё не проверены.
- Root `adb devices -l`: пустой список. Запрошено подключение именно проблемного телефона для проверки служебных metadata без текста банковских уведомлений. Pending ответ не заменяется временем ожидания; разрешения самостоятельно не выдаются.
- Подготовленный0.3.0 локальный QR/genericprefill зафиксирован отдельно v4 для суда, измененияcapture/исправление данного сбоя ему не приписываются.

Пользователь подключил проблемный основной телефон и уточнил «уведы есть ... не видит ... сколько потратилось и 0 инфы». Root проверил metadata: единственный авторизованный SM-S921B/API36, installed code2, NLS component в enabled list, активная user0 service/systembinder requested/received/hasBound=true, установлены kz.kkb.homebank и ffinbank.MyFreedom. Serial/UID/PID/privatepaths в repo не сохраняются. Ни текст, ни extras, ни финансовая DB не читались. Эти наблюдения не доказывают конкретную причину пустых полей или исправление0.3.0, но доступ и binding теперь подтверждены не только словами пользователя. Ожидается ограниченная доставка проверенного genericprefill и отдельное наблюдение нового события/обезличенный пример.

Ограниченная доставка APP-016 завершена: code3/name0.3.0 подтверждены, owngrant и systembinding сохранились. Теперь нужен результат **нового** уведомления Freedom/Halyk или добровольно предоставленный обезличенный образец. Исходные rawtext ранее не сохранялись, старые пустые карточки не являются тестом нового обработчика. Телефонные финансовые записи/текст по-прежнему не читались, точная причина и реальное исправление пока не заявлены.
