# APP-010: ограниченная проверка доступности открытого чека Kaspi

- Родитель APP-009. Пользователь требует ноль действий после каждого перевода; отдельно ответил «Разрешаю только такую проверку» на описанный compatibility-check.
- Статус needs_information: глава отдельно проверил обоих специалистов; NO-GO для читающей пробы при текущих вводных. Реализации и телефонной проверки нет.
- Разрешённая область: только текст уже открытого пользователем итогового чека Kaspi — сумма/валюта/дата/статус, локально. Другие экраны, баланс, история, пароли не читаются. Никаких скриншотов, фонового опроса, открытия банка, нажатий, жестов и действий от имени пользователя. Если текст скрыт или допустимую область нельзя надёжно установить, остановиться без расширения доступа/обходов.
- Это узкое новое согласие не отменяет прежнюю границу в иных случаях. Ни production-ingestion, ни автоматическое финансовое проведение этим не разрешены; проба не пишет денежный журнал. Никаких реальных переводов ради теста не инициировать.
- Ответственный отдел architecture/security: глава + system-architect и security-engineer, реальные агенты. Главе только новый team/reports/APP-010-architecture-review.md; specialist contracts docs/android/APP-010-COMPATIBILITY.md и security docs/android/APP-010-SECURITY.md. Они не меняют продукт/402frozenфайла/старые вердикты.
- Критерии предварительной проверки: установить реальную возможность ограничить чтение ДО обращения к тексту; ручной одноразовый запуск проверки при уже открытом чеке вместо постоянного наблюдения; package/current-user/window/receipt-state/password/sensitive/hidden/missing guards, отсутствие ложного isAccessibilityTool, отсутствие screenshots/actions/network/raw persistence. Честно описать, какие gates возможны без чтения других банковских экранов и без известных view IDs. Если безопасного gate нет — не строить сервис, нарушающий обещанный scope.
- Допустимый будущий прототип только после положительной проверки двух специалистов и главы, отдельный пакет без вмешательства в установленную финансовую БД; никакое разрешение не включается root автоматически. Независимый QA и суд до выдачи нового проверяемого APK пользователю. Фактическая совместимость Kaspi остаётся неизвестной до отдельной пробы; generic Android API не является её доказательством.
