# APP-005 — независимая первоначальная позиция адвоката пользователя

## Задача и версия

Защищаю запрос U4/U5: Android, доходы/расходы, категории позднее, автоматические чек→расход и уведомление→операция; желаемый охват «все банки». В реализации не участвовал. Другие судебные позиции не читал и выводы не согласовывал.
Версия `android-alpha-v1`, 108 файлов, manifest digest `87b8a045ac6e104e802cca11e6bbae40cceb5d688e13e681e654a990f4f99864`; APK SHA-256 `38c9d4490419eda3685e7187281d5f1ecfb958a95d77c57f7f59633febcfbd5a`.

## Выполненное и доказательства

- Прочитаны AGENTS/PROTOCOL, полный профиль роли, дело, A1–A6, PERSONAL-MVP/AUTO-ENTRY, README, QA-head/scenario отчёты; адресно проверены пользовательские тексты `view.js`/`app.js`. Продукт не менял, приложение не запускал.
- Собственная read-only команда: Python stdlib `json/pathlib/hashlib` через PowerShell here-string → для каждого `snapshot.files` проверить bytes/SHA, затем SHA строки `sha256 + two spaces + path + LF`. Ожидание: 108 совпадений, исходный digest/APK. Факт: exit0, 108 файлов, `mismatches=[]`, оба SHA совпали. Это проверка идентичности пакета, не функций Android.
- [Независимый QA](../reports/APP-005-qa-review.md): 211 JVM/39 hostSQLite assertions, 17 CUA browser groups, 55 APK checks PASS; root 24 JUnit PASS. Их выполнение себе не присваиваю. В тех же доказательствах явно отсутствует Android execution.
- [Руководство](../../android-app/README.md) и `view.js:230–240,370,395–399` объясняют дату уведомления, необязательную категорию, раздельные валюты, выбранные источники, местное хранение и риск потери записей. Синхронизация/общий бюджет для отца не запрошены; их отсутствие не считаю нарушением.

## Замечания

**USR-01 / P2 / подтверждён пробел доказательств, отказ продукта не установлен.** Полная пользовательская цель A2–A5 не доказана: браузерная память не подтверждает сохранение Android-записей после остановки процесса, JVM parser не подтверждает доставку NLS или OCR JNI→SQLite. Источники: [дело, «Не выполнялись»](APP-005.md), [QA, матрица A1–A6](../reports/APP-005-qa-review.md), [сценарный отчёт](../../android-app/qa/scenario/REPORT.md).
Практическое следствие: пользователь ещё не может полагаться на APK как на проверенный личный учёт. Для полной приёмки нужен Android-проход: пустая установка→настройка→доход/расход без категории→категория→перезапуск; ясный/сомнительный чек через камеру/изображение; доход/расход из уведомлений; повтор, исправление, чек+уведомление и post/link/ignore без двойного итога. Проверять точные суммы/валюты/даты, а не только появление экранов. Это проверка имеющихся A2–A5, не новая функция.

**USR-02 / P2 / подтверждено ограничение охвата, универсальный отказ не установлен.** «Все банки» остаётся пользовательской целью U5; общий parser и наличие listener не доказывают её выполнение. Внешние реальные форматы/скрытие текста и доставка не испытаны. Источники: [PERSONAL-MVP U5/R5](../../docs/product/PERSONAL-MVP.md), [A3](../tasks/APP-005.md), README «Границы версии».
Практическое следствие: нельзя обещать, что уведомления пользователя или отца будут распознаны автоматически. Сохранить цель открытой; проверить доступные форматы на размеченных обезличенных примерах и Android-доставке, публиковать только фактическую проверенную область. Не требовать от пользователя передавать личные сообщения для самой передачи альфы. Не превращать неизвестные сообщения в успешный автопост.

**USR-03 / P2 / подтверждена неоднозначность передачи; устраняется явным сообщением без изменения замороженного APK.** README начинает с «Локальное приложение», шаг 4 — «OCR работает на телефоне»; прямое перечисление невыполненных Android-сценариев вынесено в технические отчёты. Пользователь может получить более сильное впечатление готовности, чем позволяет QA. Источники: README начало/шаг 4/последний пункт «Границы версии»; [A6](../tasks/APP-005.md).
При передаче прямо написать: debug APK для личной установки и проверки, установка/запуск Android, native-сохранение, камера/OCR и реальные банковские уведомления ещё не исполнялись; «все банки» не подтверждены. Рядом указать отсутствие экспорта/восстановления и отдельные базы двух телефонов. Отсутствие экспорта не объявляю новым блокирующим требованием.

## Оценка приёмки и оставшиеся вопросы

A1 подтверждён в части реального артефакта/сборки; запуск на конкретном телефоне не установлен. A2–A5 частичны; A6 получит судебное завершение после обмена и вердикта. Подтверждённых неверных расчётов или воспроизводимых P0/P1 в рассмотренных материалах не нашёл; QA-CALC01 исправлен и перепроверен настоящим JVM-тестом, без доказательства всего OCR-маршрута.
Открыты конкретный Android/устройства и фактический корпус банковских сообщений/чеков. Возможное использование отцом означает второй локальный экземпляр; семейная синхронизация не следует из запроса.

## Рекомендуемое следующее действие

Полная функциональная приёмка: `insufficient_evidence` по USR-01/02; не объявлять A1–A6 полностью выполненными. Передача этой подписанной устанавливаемой альфы допустима для личной установки и следующей проверки при явном сообщении USR-03 и прямой ссылке на руководство. Это полезный промежуточный результат по исходной цели, а не её полное выполнение. После раскрытия отвечу на конкретные возражения обеих сторон.
