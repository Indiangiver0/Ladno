## Проверка и интерес пользователя

Прочитаны AGENTS/PROTOCOL/полный профиль, общий пакет, финальные QA/backend/TLS отчёты, безопасный `authorized-live-evidence.json` и строки 52–55, 508, 515 `view.js`. Read-only Python подтвердил фактический SHA основного APK и метаданные manifest (170 файлов). Новых сборок, HTTP, установки, финансовых записей или UI испытаний не выполнял. Чужие судебные позиции не читал.

Пользователь просит избежать ручного заполнения после сканирования бумажного чека. Доказан существенный полезный результат: обычный Android-клиент получил от официального ОФД **4395.00 и 3547.00 KZT** за **03.11.2026**, с подтверждением продажи и совпадением реквизитов. Для второго чека взят окончательный итог после скидки. Точность — две десятичные позиции, без округления; POS-слип 490 не считается дополнительной покупкой. Реальные lookup были read-only; запись ровно одного расхода и сохранение ручных решений проверены отдельно на synthetic pipeline. Эти два вида доказательств нельзя объединять в утверждение, что пользователь уже успешно отсканировал чек камерой.

## Существенные пункты

- **APP017-DEC-01 / P1, подтверждённый открытый отказ:** два предоставленных фискальных фото **545/490 KZT** не декодируются. Это препятствует основному сценарию на половине четырёх покупок. Нельзя принять общую задачу или назвать все чеки исправленными. Требуются читаемые крупные QR либо доказанное улучшение декодера; владелец — backend/data, повторная независимая проверка на исходных и новых входах.
- **UA17-UI / P2, недостаток доказательств:** камера → видимый результат → журнал на физическом телефоне не испытаны. Нужен один реальный скан с проверкой суммы/даты и отсутствия дубля; большие числа тестовых assertions это не заменяют.
- **UA17-RETRY / P2, признанное ограничение:** ранее созданный pending при повторе после успешного API остаётся на проверке. Это защищает пользовательские решения, но старые пустые записи не начнут сами заполняться после обновления. Не обещать такого поведения; объяснить отличие при передаче.

## Рекомендация

Общий вердикт — **revise**. Ограниченную передачу точного APK для дальнейшего пользовательского тестирования поддерживаю: известный ОФД, один читаемый QR в кадре, интернет, проверка итогового результата; без обещаний всех банков/всех чеков и без автоматического внесения присланных фотографий через ПК. Подсказка и сообщение о передаче только QR-реквизитов ОФД соответствуют этому объёму. Установка остаётся экспериментальной передачей, а не приёмкой всей APP-017.
