## Решения по существенным пунктам

1. **IMPL-01 / LIVE01, подтверждено; прежний LIVE01/P1 закрыт в проверенном объёме.** [Live evidence](../../android-app/qa/app017/authorized-live-evidence.json) содержит ordinary default Android client, verified final SALE, **4395.00 / 3547.00 KZT**, дата **2026-11-03**, expense/high. Финансовая точность — scale2 без округления; для второй покупки принят окончательный итог после скидки. Это реальный запрос ОФД, а не только mock/cached parser. `ledgerIngestCalled=false`, `uiExercised=false`: записи этих покупок и полный телефонный сценарий из этого доказательства не следуют. Старые SSL FAIL сохранены и относятся к прежним попыткам. Защиту реализации признаю по фактам, независимо от согласия сторон.

2. **DEC-01 = APP017-DEC-01 / P1, подтверждён и открыт.** Backend и независимый QA фиксируют исходный результат 0/0/0/1/1: фискальные фото **545/490 KZT** не декодируются; отрицательное исследование не исправило декодер. Это препятствует заявленной автоматизации предоставленных четырёх покупок и блокирует общую приёмку. POS-слип490 не пятый расход. Владелец — backend/data. Нужны крупные читаемые QR либо доказанная общая стратегия декодирования. QA повторяет исходные входы и новые снимки раздельно: успех нового фото не объявляется исправлением старого.

3. **UI-01 = UA17-UI = QA17-02 / P2, пробел доказательств открыт.** Реальный lookup и synthetic registered Job→SQLite проверяют разные части; ни один не доказывает camera/gallery→видимый журнал на физическом телефоне. Установленная поломка UI не доказана. Frontend/backend предоставляют сценарий, независимый QA проверяет реальный скан одной покупки, точные сумму/дату/статус и повтор без второго расхода; отдельно фиксирует результат обновления. До этого полного end-to-end заявления нет.

4. **IMPL-02 / UA17-RETRY, защита повторов подтверждена в synthetic объёме; P2 ограничение сохраняется.** 187 native assertions и проверки глав поддерживают неизменность пары прежних source/revision токенов, сохранение ignored/edited/linked/deleted решений. Поздний API success не заполняет старый pending автоматически. Признаю обоснование защиты ручных решений, но не считаю неудобство устранённым. Chief раскрывает это при передаче. Дальнейшее обогащение pending — отдельный контракт product/backend с QA сохранения правок и недублирования.

5. **NEIGHBOR-01 = QA17-01 / P2, открыт.** Старый damaged-neighbor diagnostic skipped, не PASS. Несколько обнаруженных QR отклоняются, однако обнаружение повреждённого соседа не доказано. Backend владеет дальнейшим решением, QA — соответствующими входами; ограниченная передача требует одного QR в кадре и сверки результата.

6. **TLS-01 = QA17-03 / P2, предел охвата, установленной уязвимости нет.** Security/architecture подтверждают исходный DEFAULT validator, прежние anchors/hostname verifier и недоверенный промежуточный chain element; native transport прошёл. Сохранены 4 lint warnings, включая CustomX509TrustManager. Spies/wrong-peer не доказывают весь PKIX/Engine/revocation набор. Architecture/security отвечают за повторную оценку при изменении TLS/issuer/платформы; универсальная гарантия не разрешена.

## Ограниченная передача и дальнейшая приёмка

Разрешаю передать указанный exact APK как ограниченное development-обновление: известный `consumer.oofd.kz`, читаемый QR, интернет, подтверждённая SALE плюс существующие dedup/review gates. При USB-доставке — только подтверждённый телефон, обычное обновление без удаления данных, readback версии; отсутствие устройства не выдаётся за установку. Сообщить пользователю о двух нечитаемых QR, непроверенном физическом сценарии и неизменных старых pending. Фото остаются локально, ОФД получает разрешённые QR-реквизиты; присланные образцы через ПК в пользовательский журнал не проводятся.

Freedom/Halyk и отсутствующие исходящие Kaspi OS-события этим решением не исправлены. Незакрытый P1 не позволяет объявить APP-017 принятой. После исправления/уточнения DEC-01 и независимой проверки затронутых сценариев — повторный суд по новой зафиксированной версии. Старые вердикты сохраняются.
