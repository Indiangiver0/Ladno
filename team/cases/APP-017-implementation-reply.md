# APP-017 — ответ адвоката реализации после раскрытия

2026-11-04, `/root/app017_implementation`. Прочитал все три первоначальные позиции. Версия прежняя: frozen android-alpha-v5, APK SHA `f54733b034399ec0b147d0fa7e9b5b82a8589034ca5c8692b63c905a2aa37cd3`. Новых тестов, HTTP, установки или изменений frozen материалов не выполнял.

**DEC-01/P1:** согласен с критиком и адвокатом пользователя. Наличие рабочего API не исправляет нечитабельный QR. Backend/data сохраняет владение decoder-пунктом: получить крупные QR545/490 либо реализовать новую общую стратегию; независимый QA явно различает повтор исходного фото и проверку нового снимка. Исходный FAIL нельзя закрыть успехом другого входа без оговорки. Общий `revise` поддерживаю.

**UI-01/P2 = UA17-UI:** признаю пробел, но данных о поломке UI нет. Ответственный frontend совместно с backend предоставляет проверяемый сценарий; независимый QA должен отдельно проверить физический скан одного читаемого чека, сумму/дату в видимом журнале и повтор без дубля. Live lookup был без ingest, synthetic внутренний Job не заменяет этот этап. Отсутствие проверки запрещает заявление о полном end-to-end, не обесценивает actual Android API4/5.

**NEIGHBOR-01/P2:** multiple-decoded guard защищает лишь от нескольких обнаруженных QR. Пропущенный damaged-neighbor diagnostic не PASS. Backend владеет улучшением/ограничением выбора, QA — повторной проверкой этого класса входов. До этого ограниченная передача требует одного QR в кадре и сверки результата.

**TLS-01/P2:** согласен с обозначенным пределом, установленной уязвимости нет. Default trust anchors/hostname verification сохранены; public/default-client PASS доказывает конкретный transport. Architecture/security владеет дальнейшей оценкой при изменении TLS-кода/issuer/платформы; отдельные реальные PKIX/Engine negatives потребуются для соответствующих расширенных заявлений. Существующие spies ими не считаю.

**UA17-RETRY/P2:** признаю неудобство старых pending. Стабильная пара токенов сохраняет прежнее решение; молчаливое продвижение могло бы затереть ручную правку. При передаче chief должен прямо сказать: обновление само не заполнит старые пустые кандидаты. Если потребуется безопасное повторное обогащение, backend/data с product задают отдельный контракт, QA проверяет сохранение правок и отсутствие дублей. Сейчас это не исправлено.

Поддерживаю отдельную ограниченную development-передачу exact APK с перечисленными условиями; общую приёмку не поддерживаю. Окончательное решение — независимому судье.
