# APP-006 — ответ адвоката пользователя после раскрытия

Дата: 2026-11-03, Asia/Qyzylorda. Версия `android-alpha-v2`, digest `b92d7a8f600e73720c415ad18579aaf70ec2166e1ca4a3009314cce1aec6bc16`; production APK прежний `38c9d4490419eda3685e7187281d5f1ecfb958a95d77c57f7f59633febcfbd5a`. Независим от production/tests/evidence.
Выполнено: `Get-Content` трёх раскрытых initial; ожидание — конкретные ответы по новой дельте, факт — существенных разногласий не выявил. Новых тестов/аудита не проводил, frozen215 не менял; источники: [критик](APP-006-critic.md), [реализация](APP-006-implementation.md), [QA-head](../reports/APP-006-qa-review.md).

- **C006-01 / P2 и IA005-01/USR-01:** признаю подтверждённое частичное закрытие. Native persistence/точные итоги/категории/повторы и безопасные решения действительно исполнены на Android; 388 assertions — шесть instrumentation-команд, не UI-тесты. Остаток — MainActivity/WebView/формы→bridge, выбор источника/первый grant, камера/галерея→зарегистрированный job→видимый результат. Нужен адресный сквозной проход, без повторения native PASS без причины. Отказ продукта не доказан.
- **C006-02 / P2 и IA005-02/USR-02:** согласен, реальная доставка ОС синтетических уведомлений не доказывает работу конкретных банков. «Все банки» остаётся открытой целью, проверенную область нельзя расширять обещанием. Реальные обезличенные форматы/фото и ARM/OEM — границы доказательств; новые обязательные функции или универсальный отказ из них не вывожу.
- **C006-03 / P2 и IA005-03:** согласен с единичным false negative KZ paid: safe review подтверждён, автоматическое занесение этого чека не произошло. Масштаб неизвестен, неверного денежного итога не установлено. Реально проведены два EN/RU paid, не шесть изображений. Нужен размеченный корпус с отрицательными unpaid-регрессиями; ослабление finality ради формального PASS не защищает пользователя.
- **IA, новая дельта:** признаю реальность AndroidKeyStore, настоящего NLS callback после readiness и Tesseract JNI→SQLite. Старые три FAIL не скрыты; setup/orchestration причины не превращаю в production P1. При этом readiness-тест не подтверждает первую доставку сразу после пользовательского разрешения. Полная цель A2–A5 остаётся обязательной, native-часть её уже доказана.

**USR-03 / P2:** условие актуальной коммуникации закрывается только реально отправленным финальным сообщением рядом с APK/[руководством](../../android-app/README.md), не наличием цитаты в протоколе. Изменять frozen215 не требуется. Минимально понятная оговорка:

> Это debug-альфа «Ладно» для личной установки на Android 8+. На эмуляторе Android 11 проверены сохранение и точные итоги, реальная доставка тестовых уведомлений и распознавание тестовых чеков через Tesseract. Интерфейс Android-приложения, камера/галерея и полный путь обработки через экраны ещё не проверены; реальные банки, фото чеков и физические ARM-телефоны/другие производители тоже. Все банки и автоматическое распознавание казахских чеков не подтверждены. На двух телефонах отдельные базы без синхронизации; экспорта и восстановления нет — удаление приложения или потеря телефона может привести к потере записей. Полная приёмка пока не выполнена.

Рекомендация по полной задаче остаётся `insufficient_evidence` по остаточным обязательным путям/покрытию; передача текущего APK как альфы допустима отдельно с этой оговоркой. Экспорт/синхронизацию новыми требованиями не делаю, риск единственной копии сообщаю. Подтверждённых открытых P0/P1 не заявляю; оставшиеся вопросы — устройство/корпус и адресный UI/media/permission проход. Решение о достаточности принимает отдельный судья по всему спору.
