## Позиции по существенным пунктам

**IMA-01 — OCR исправление обосновано в проверенном объёме.** Факт, не новый дефект. Guard до `ingestCandidate` требует complete/high/no-reasons обоих результатов, confidence каждого≥80 и точного совпадения kind/amount/currency/date. При расхождении сохраняет primary поля, добавляет LOW_CONFIDENCE и запрещает high. В actual неизменённом PNG754.32 BEST даёт754.32, FAST794.32; записан review754.32 без неправильного расхода. Отдельные123.45 и6543.21тг действительно проведены, поэтому автоматизация не заменена безусловной ручной формой. Ошибка прежней FAST-модели признана и устранена для воспроизведённого контрпримера. Основание: native71 pairs и QA report; алгоритм соответствует APP-008-CONTRACT. Согласованные ошибки двух родственных моделей остаются возможны: это ограничение, не доказательство нового финансового P1 и не гарантия безошибочности.

**IMA-02 — сохранность и точность имеют предметные доказательства.** Факт, подтверждён. Seed выполняется в onCreate/upgrade1→2, а не при state; stable IDs и нормализованные kind/name включают tombstones. Исходные таблицы не пересоздаются. Actual39 migration pairs проверяют fresh/empty-v1/populated-v1, сведения и revisions, сохранение HMAC/связей, удаления/переименования. График агрегирует BigInt minor units, сверяет total с native expense; в Number переходят только bounded доли/геометрия. Проценты распределены largest remainder10000bps; доходы исключены, null включён, Other не стирает полную легенду. QA269+211 и60 групп/3840 сравнений, browser-сценарии и непрерывность шести assets убедительно поддерживают A2/A4. Я не выдаю число сравнений за число независимых запусков приложения.

**IMA-03 — новые действия используют существующие транзакционные границы.** Факт, подтверждён кодом и отдельными CUA-сценариями. Inline-category делает самостоятельный saveCategory без submit незаконченной операции; draft восстанавливается, новый ID выбирается после commit. «Убрать» адресует только pending receipt, подтверждается и вызывает reviewCandidate/ignore с ожидаемой revision. Это сохраняет dedup и не создаёт расход. Safe Job.outcome проецируется из результата commit, raw OCR не передаётся в JS; failed/cancelled не объявляются сохранённым расходом. Решения соответствуют просьбе убрать три повторных скана и удобству пустой установки. Browser harness подтверждает контроллер/вид, а не исполнение native WebView bridge.

**IMA-04 — пробел интеграционной приёмки, P2 / недостаточные данные для полного camera-сценария.** Подтверждённое отсутствие доказательства, не воспроизведённый продуктовый отказ. Не выполнен путь физическая камера→registered Activity job→native WebView→видимый outcome на этой версии; нет исходного фото пользователя, полного bank/photo corpus, peak JNI memory и cold phone timing. Native API и browser CUA хорошо проверяют отдельные части, но логически не заменяют этот путь. Точный исходный отказ пользователя поэтому нельзя объявить устранённым. Действие: после доступного USB выполнить один обычный скан исходного/представительного бумажного чека и проверить видимый результат/разбор; до этого честно сохранить alpha-границу. Для утверждения именно полного A1 этих данных недостаточно; смягчать критерий задним числом нельзя.
