# Дело APP-013/014: локальный QR и предзаполнение уведомлений

Статус: начало независимых позиций после фиксации. Root владеет только пакетом дела/раскрытием/карточками, не вердиктом.

## Запрос и фактический объём

Пользователь после тестов сообщает ограниченный захват доходов/расходов/переводов и просит подключить API для данных из QR чека. Назвал Freedom/Halyk помимо Kaspi, но реальных текстов уведомлений не предоставил. Не смог определить сайт/данные QR; снимок фактического чека пока отсутствует. Требование из предыстории — сократить ручные действия, включая исходящие переводы. Отсутствующие системные события Kaspi раньше подтверждены пользователем; APP-010 узкое разрешение bank-screen проверки не расширялось, архитектурное NO-GO не отменено.

Версия 0.3.0/code3 реализует только часть: локальный strict QR decoder двух известных KZ фискальных форматов + generic захват полей уведомления/валютных алиасов/направлений. Сетевой API ОФД НЕ реализован, успешная схема ответа не подтверждена; наличие consumer страницы не объявлено API. Полная автоматизация банков и покрытие Freedom/Halyk не достигнуты. Суд не должен подменять эту исходную цель узкой подзадачей.

Суду предлагается общий вердикт по доказательствам и отдельное мотивированное решение: допустима ли передача точного APK как ограниченной экспериментальной сборки с явными границами, без заявления API/all-bank готовности. Это не запрос на публикацию/постоянную установку/изменение разрешений телефона.

Root не приписывает generic parser patch исправление этой проблемы. Ни исходный payload, ни точные persisted package/profile, ни результат нового события в журнале не проверены.

Смежный APP-015 read-only triage (`team/reports/APP-015-capture-triage.md`, вне frozen продукта) выполнен реальным backend head и explorer: grant UI не доказывает connected listener; review-list глобален, но auto-post/duplicate/ignore могут не дать новую карточку; причина unknown, sourcefix не внедрён. ## Порядок слушания

Три разные независимые стороны сначала читают только общий пакет и пишут собственные позиции (не читают позиции других). После root-раскрытия — один раунд ответов всем относящимся существенным пунктам. Затем отдельный четвёртый агент-судья читает пакет/позиции/ответы и пишет мотивированный вердикт; root его не переписывает. Фактические ID и frozen manifest добавляются после реальных действий.

Реально запущенные стороны: `/root/qr_court_critic`, `/root/qr_court_implementation`, `/root/qr_court_user`. Каждая получила один общий packet/frozen manifest и отдельное владение своим initial файлом, запрет читать чужие позиции до раскрытия. Судья ещё не запускался.

Все три первоначальные позиции получены независимо и раскрыты сторонам: APP-013-critic-initial.md, APP-013-implementation-initial.md, APP-013-user-initial.md. Все признают отсутствие API и неподтверждённое исправление Freedom/Halyk; разная оценка тяжести API-пункта (критик P1 невыполнение основного запроса, адвокаты P2 ограничение/недостающая часть) передаётся в мотивированное решение судье. Root не меняет их оценки. Начат один раунд ответов после раскрытия; собственные response файлы сторон вне frozen140.

Раунд ответов завершён: APP-013-critic-response.md, APP-013-implementation-response.md, APP-013-user-response.md. Критик после прочтения initial защиты снизил API-пункт до P2 как обязательную незавершённую часть; оба адвоката после прочтения initial критика повысили его до P1 для основной цели. Это фактическое расхождение сохранено, повторное согласование/голосование не проводилось. Все три стороны блокируют общую готовность и отдельно допускают ограниченную экспериментальную передачу точного APK при раскрытии границ. Решение тяжести/общего вердикта и допустимости передачи выносит отдельный судья.

Root повторно выполнил adb inventory: пусто. USB-метаданные Freedom/Halyk и новый банковский callback не получены; причинный диагноз не появился. Эти неизменённые факты переданы судье, новых тестов/изменений frozen140 после фиксации не было.

### Дополнение перед запуском судьи

Пользователь подключил телефон и уточнил: «уведы есть, система просто не видит почему то сколько потратилось и 0 инфы». Различие между отсутствием карточки и карточкой с пустыми полями по этому тексту остаётся неоднозначным; root не присваивает окончательный диагноз.

Root read-only metadata на единственном новом авторизованном подключении: основной SM-S921B/API36, установлен com.ladno.finance code2 (0.3.0 туда ещё не поставлена); enabled_notification_listeners содержит BankNotificationService; `dumpsys activity services com.ladno.finance/.BankNotificationService` показывает активную user0 службу, system binding `requested=true received=true hasBound=true`, binder имеется. Package-list targetedfilter подтвердил `kz.kkb.homebank` и `ffinbank.MyFreedom`. Full serial/UID/PID/путь частных данных не сохраняются здесь. Текст/extras уведомлений/банковские записи/DB не читались; settings/permissions не менялись.

Это уточняет доступ/binding/установленную версию и исключает отсутствие этих metadata в данный момент, но **не** подтверждает доставку нового callback, сохранённые exact sources/profile, поля payload или исправление parser. Не называть bound metadata полноценным end-to-end. Дальнейшая установка0.3.0 требует честного ограниченного handoff, а не обещания API/FreedomHalykfix.
