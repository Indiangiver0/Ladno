## Неуспешные попытки и оценка замечаний

Сохранены3 прежних financial deadline FAIL. Первые2 использовали grant как эквивалент connected; diagnostic timing поддерживал setup-race hypothesis, но не доказывал точный момент callback. Третий повторил старый diagnostic APK до окончания новой сборки — признанная orchestration ошибка начальника. Новая установка имеет completed fingerprint guard. Эти FAIL не удалены и не названы PASS.

Readiness добавлен только в test setup: публичный безденежный OS ping→реальный needs_review commit; игнорируются только новые probe IDs, финансовый count неизменен, затем прежние финансовые assertions. Readback diff до readiness не содержит удалённых строк; настоящий финансовый путь прошёл после новой сборки. Manual callback, mock/private gate override и production fix не применялись. Backend-triage-v2 закрыл setup finding; подтверждённого production P1 в рассмотренных результатах не установлено. Причинность всех первоначальных FAIL не заменяется одним предположением.

Нормализованный host SQLite snapshot не выдаётся за сохранённые исходные DB/WAL/SHM bytes: первоначальные raw bytes не удержаны, normalization-notes явно фиксируют derived copy. Выводы N1/N2/N3 опираются также на instrumented expected/actual и команды, а не только на этот snapshot. Открытых подтверждённых продуктовых P0/P1/P2 в исполненной native API области нет; ограниченная выборка не доказывает отсутствие любых дефектов.

## Заключение для адресного повторного суда

Новые evidence закрывают прежние пробелы **N1, N2 и N3 в явно описанной native API области на одном эмуляторе**, с N4 как честным перечнем фактических форматов. Рекомендую передать неизменный APK и новый immutable пакет доказательств всем сторонам для адресной оценки. Устанавливаемая альфа теперь имеет реальное Android runtime подтверждение перечисленных путей; полная приёмка телефонных UI сценариев, реальных чеков/банков и всех устройств по-прежнему не заявляется. Суд самостоятельно оценивает достаточность этого охвата и сохраняет ограничения в мотивированном вердикте; глава QA вердикт не предрешает.
