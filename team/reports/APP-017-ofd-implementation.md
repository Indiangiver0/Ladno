2026-11-04, Asia/Qyzylorda. Исполнитель `/root/ofd_backend_engineer`, работа по назначению chief от backend-data-lead. Собственная приёмка не заявляется; результат передаётся главе и независимому QA.

## Изменения и версия

Добавлены `OfdReceiptClient`, `core/OfdReceiptParser`, `core/OfdJson`. `NativeRuntime.processMedia` после validated local QR вызывает fixed consumer client. Manifest получил INTERNET, WebView в неизменном MainActivity сохраняет `setBlockNetworkLoads(true)`. Version0.4.0/code4. Decoder/scanner, SourceTokens, LedgerStore/schema, IngestSource/bridge schema и чужие source не менялись.

Native client строит только HTTPS GET `consumer.oofd.kz/api/consumer-proxy/api/tickets/get-by-url` из strict QR полей; arbitrary QR URL не загружается. Default TLS, redirects/caches выключены, WebView cookies/credentials не копируются, body/depth/array/string/number bounds, content-type/encoding/UTF-8 checks. Caller total deadline10s (connect/read≤5s), один network daemon и bounded queue1; зависший platform DNS не создаёт бесконечные потоки/очередь и не блокирует caller навсегда. Exceptions/response/query не логируются и не передаются в JS. Не было собственных новых сетевых запросов: использована ранее полученная разрешённая схема/приватные ответы.

Custom bounded JSON reader сохраняет исходные numeric lexemes: platform Android org.json мог бы сначала округлить деньги через double. KZTscale2, ≤24 integer digits, лишние дроби/exponent/sign/zero total отвергаются, округления нет. `totalSum` — итог после скидок, товары/VAT/taken/change не пересчитываются. Обязательные fiscalId/rnm/total/QRdatetime совпадают; datetime только source components и optional `.000`, без offset/+2h.

Только typed TICKET, op2 SALE, явные cancelDate/offlineFiscalId null, согласованная сумма CARD/CASH/MOBILE payments и известный item/status subset дают expense/high. Unknown/refund/cancelled/offline/linked или противоречивые данные не auto-post. Items1 commodity и наблюдавшийся items5 discount допустимы; raw customer/payload/requestPayload/responsePayload остаются transient и отсутствуют в candidate. acceptedAt/kkmId не financial evidence/revision.

Ошибки сети оставляют полезные QR amount/date и один unknown-kind review с OFD_UNAVAILABLE; malformed/schema — OFD_INVALID_RESPONSE; несогласованные identity/total/date — OFD_MISMATCH; непроверенный тип/состояние — OFD_REVIEW_REQUIRED. Нужны русские UI labels этих новых reasons у frontend владельца.

## Replay и ручные решения

Оба observation токена сохранены **побайтно по0.3.0**: source HMAC `receipt-fiscal-qr-v1 + qr.locator()`, revision HMAC того же purpose + locator + исходный `qr.revision()` (amount,timestamp). API confidence/type/items/rawmetadata токены не меняют. Уже существующий atomic exact source+revision lookup в LedgerStore возвращает прежний candidate/record до auto-post, независимо от отредактированных суммы/даты. Это закрывает designgap OFDSEC-01 без миграции/alias/new-source схемы.

Pending local/network fallback при последующем API success безопасно остаётся **той же review карточкой**; отдельного in-place promotion не добавлял. API не создаёт вторую карточку/expense. Это ограничение автоматизации существующей pending, не ложный auto-success. Posted/ignored/linked и deleted transaction не должны оживать.
