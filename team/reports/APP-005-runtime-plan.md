# APP-005 — план независимого Android runtime QA N1–N3

Дата: 2026-11-02, Asia/Qyzylorda. Автор плана: `/root/android_qa_lead`. Статус: только план; Android-тесты этим этапом не созданы и не запущены. Исторические frozen108/v1, прежний QA-отчёт и судебное `insufficient_evidence` не изменяются. Новый пакет доказательств потребует собственного fingerprint и повторного судебного рассмотрения.

## Условие запуска и границы

Начальник сначала подтверждает доступность официального эмулятора/ускорителя и адрес конкретного выделенного тестового устройства. Если capability не прошёл, специалисты не занимают слоты ожиданием; Windows BIOS, драйверы и security settings не изменяются. ADB не направлять на личный телефон. Все данные — синтетические, очистка допустима только у явно выделенного тестового package на этом эмуляторе, после проверки serial/package; не касаться пользовательских баз и аккаунтов.

Два независимых специалиста исполняют AndroidJUnitRunner из имеющихся test dependencies (`androidx.test:runner`, ext:junit). Native данные вызываются через настоящие production APIs; Python-копии, Mockito вместо SQLite/Tesseract/Keystore и обход приватных проверок NLS не считаются выполнением N1–N3. Не использовать ActivityScenario/Espresso/UIAutomator или ADB input для UI: UI-действия только CUA. Headless API-проход не доказывает работу системного picker, внешней камеры, клавиатуры или WebView.

Root владеет build/SDK/emulator/run scripts и интеграцией сборки. Специалисты владеют только новыми androidTest-файлами, перечисленными ниже, и своими новыми evidence-каталогами. Production Java/Manifest/assets и чужие тесты не менять. При необходимости изменения продукта — finding с воспроизведением владельцу. После двух передач — отдельный review главы QA, затем независимый суд; автор не принимает собственную работу.

## Специалист 1 — calculation-test-engineer, N1

Предлагаемое владение: `android-app/app/src/androidTest/java/com/ladno/finance/storage/LedgerRuntimeWriteTest.java`, `LedgerRuntimeReadTest.java`, `LedgerRuntimeFixtures.java` в том же каталоге; evidence только `android-app/qa/runtime-ledger/**`. При запуске передать полный профиль `.cursor/agents/calculation-test-engineer.md` и этот план. Если специалист уже занят, начальник запускает от имени главы после освобождения слота.

Настоящие сигнатуры: `LedgerStore.get(Context)`, `state(String month,String currency):JSONObject`, `execute(String action,JSONObject payload):JSONObject`, `ingestCandidate(JSONObject source,ImportCandidate candidate):JSONObject`. `ImportCandidate.fromJson(JSONObject)` создаёт строго контрактный DTO. Хранилище — настоящий Android SQLiteOpenHelper/ledger.db, а не host SQLite. `LedgerStore` singleton не имеет public reset/close; нельзя выдать повторный вызов get за перезапуск.

- N1a: на чистом тестовом приложении state пуст; settings с primaryCurrency=KZT, zoneId=Asia/Qyzylorda, datePolicy=POST_TIME_IN_ZONE. Через execute создать income/expense/category, nullable category, проверить canonical строки и реальные summary по месяцу/валюте. Примеры: 0.10+0.20=0.30, значение выше2^53, агрегат длиннее24 целых цифр, KZT отдельно от USD, граница октября/ноября.
- N1b: saveTransaction с id=null/expectedRevision=null; редактирование с фактическими id/revision; stale revision обязан дать ContractException с конфликтом и не менять запись/итог. Изменить и удалить используемую категорию: сумма/дата сохраняются, categoryId становится null. Неверные money/date/category payload не оставляют частичный commit.
- N1c: saveSources и ingestCandidate с синтетическими scoped hex64 source/revision/account/reference tokens по CONTRACT. Проверить exact replay без второго расхода; ручная правка→replay не перезаписывает её; delete→replay не воскрешает запись; новый revision и weak amount/date match требуют review; strong consistent identity связывается, не суммируется второй раз. Через execute(reviewCandidate,...) проверить post/link/ignore/CAS/confirmDistinct и нулевой вклад непроведённых материалов.
- N1d: WriteTest сохраняет набор и контрольные id/revision/ожидания в test-only private файл, завершается. Начальник запускает ReadTest отдельным instrumentation process без очистки app data. ReadTest фиксирует новый PID и через новый LedgerStore.get читает те же сохранённые значения/итоги, категории, решения импорта и tombstone/replay. Отличающиеся PID плюс две реальные am instrument команды — доказательство process restart; если процесс не сменился, писать только ограниченный reopen/readback и не закрывать persistence-by-restart.

Payload keys не упрощать: saveTransaction=`id,expectedRevision,kind,date,amount,currency,categoryId,note`; saveCategory=`id,expectedRevision,name,kind`; settings=`primaryCurrency,zoneId,datePolicy`; остальные source/review DTO строго CONTRACT v2. Сохранять фактические exception code, SQLite/runtime API level и каждое ожидание/факт.

## Специалист 2 — scenario-test-engineer, N2 и N3

Предлагаемое владение: `android-app/app/src/androidTest/java/com/ladno/finance/NotificationRuntimeTest.java`, `OcrRuntimeTest.java`, `CaptureRuntimeFixtures.java`; при отдельно разрешённой actual-delivery проверке также test-only `android-app/app/src/androidTest/AndroidManifest.xml` и `SyntheticNotificationPublisher.java`. Evidence только `android-app/qa/runtime-capture/**`. Полный профиль `.cursor/agents/scenario-test-engineer.md` плюс этот план. Package `com.ladno.finance` нужен для существующих package-private APIs, не для изменения их видимости.

**N2a — Android native capture data path.** Настоящие вызовы: `new SourceTokens(Context)`, `listenerConnected()`, `notification(namespace,rawKey,rawTag,postTime,text)`, `removed(...)`, `captureGap()`, `hmac(purpose,namespace,fields...)`; `BankMessageParser.parse(text,postTime,zoneId,allowPostTimeDate)`; `NativeRuntime.safeCandidate(candidate,uncertain)`; `LedgerStore.ingestCandidate`. Проверить фактический AndroidKeyStore HMAC (hex64, стабильность в рамках lifecycle/сохраняемого ключа, namespace/revision разделение), raw полей нет в persisted state, completed/negated/planned/hidden amount, replay/edit/delete, новое наблюдение после gap и безопасный review. При недоступном Keystore записать настоящий UNAVAILABLE и отсутствие автоматической записи; не генерировать fallback key для прохождения теста.

**N2b — actual NLS delivery отдельно от N2a.** `BankNotificationService.onNotificationPosted(StatusBarNotification)` ставит задачу в worker; private capture сначала проверяет `NativeRuntime.notificationAccess()`, setup и source allowlist, затем читает extras. Без реального OS доступа прямой callback — no-op и не доказывает приём уведомлений. Не подменять private gate/reflection/mock. Actual delivery возможна только если начальник разрешил соответствующий доступ исключительно на выделенном синтетическом эмуляторе: test package публикует Notification через свой NotificationManager/channel, приложение получает настоящий system callback. Использовать selected и unselected synthetic source, completed и negated сообщение, exact update/replay, revoke/disconnect; polling с deadline по реальному store/state. Выдачу/отзыв доступа и способ запуска явно записать. Если эта граница не разрешена/недоступна, N2b остаётся невыполненным, N2a не переименовывать в NLS end-to-end. Реальные банки и все OEM версии не покрываются.

**N3a — настоящий Tesseract JNI.** `new OcrEngine(targetContext)`, `initialize()`, `state()`, `recognize(File):OcrEngine.Result{text,confidence}`, `release()`. Создать test-only Bitmap/Canvas с крупным чёрным текстом на белом: PAID, TOTAL 123.45 KZT, 2026-11-02; сохранить в private PNG. Это создание fixture, не управление UI. Исполнить реальные bundled eng+rus+kaz модели, записать распознанные text/confidence только синтетического образца, проверить ReceiptParser.parse(actualText) по ожидаемым amount/currency/date и finality. Отдельно пустой/не-image файл должен дать настоящий IMAGE_INVALID без ложной операции. Нельзя одновременно инициализировать отдельный OcrEngine и singleton OCR: оба пишут одинаковые model .copy файлы; делать эти части последовательно с release и в отдельном чистом тестовом процессе.

**N3b — настоящий NativeRuntime image→OCR→SQLite pipeline.** В package com.ladno.finance доступны `NativeRuntime.get(Context)`, `newCameraFile()`, `processMedia(String jobId,Uri selected,File camera)`, `state(month,currency)` и store. Сначала setup; generated fixture записать в возвращённый private capture-файл; вызвать processMedia с file. Worker сам выполняет digest, recognize, confidence guard, ReceiptParser, safeCandidate, AndroidKeyStore HMAC и ingestCandidate, затем удаляет временный файл. Poll с deadline до удаления файла и устойчивого ожидаемого DB state; одинаковые image bytes не дают второго расхода; invalid image не меняет суммы. Зафиксировать, был ли фактически posted или review/LOW_CONFIDENCE/IDENTITY_UNCERTAIN; не объявлять автопроведение, если guard его остановил.

У processMedia нет возвращаемого Future, а зарегистрированный UI job обычно создаётся queueAction, требующим MainActivity. Без UI arbitrary test jobId не даёт штатного job-result; удаление файла/DB state подтверждает ограниченный data path, а не job lifecycle. Не создавать фиктивный MainActivity и не подменять jobs ради pass. Проверка `Uri selected`/FileProvider и системных chooser/grants остаётся отдельной, если её нельзя исполнить реально. Camera-file API path не равен тесту камеры/галереи.

## Доказательства и приёмка

Для каждого N: source/APK/test-APK SHA, serial/ABI/API level, команды assembleAndroidTest/install/am instrument с exit codes, JUnit XML/logcat только своего тестового package без личных данных, отдельные input/expected/actual, PID для restart. Ограниченные timeout/poll без бесконечного ожидания. Сначала capability result, затем два реальных специалиста; после исполнения глава проверяет их отчёты. Наличие тестового кода или успешная компиляция test APK не является выполнением N1–N3. Судебный вердикт frozen108/v1 сохраняется как история независимо от будущего результата.
