## Собственная проверка главы

1. Спецификация согласована с денежным контрактом: точные положительные minor, агрегаты без ограничения 24 цифрами, отдельно month/currency/scale, только расходы из действующих `records`; импорт не прибавляется повторно. Null-категория входит в полный итог. Сумма разреза проверяется на точное равенство `summary.expense`.
2. Проценты: распределение 10000 целых пунктов методом наибольших остатков по исходным группам, ASCII-ключ для ничьей; сортировка легенды по точной сумме. «Остальные» складывает исходные суммы и пункты. Перераспределение после группировки запрещено.
3. Геометрия: накопленные границы `floor(1000000000*C/T)`; перевод в Number только уже ограниченного целого. Последняя граница — полный круг, малые доли не искусственно увеличиваются; полный текстовый разрез остаётся доступным. Нулевая сумма отдельно, без деления.
4. Выполнена команда PowerShell `@' <независимый Python 3 пересчёт> '@ | python -` из корня проекта. Вход — точный JSON выше; код не импортировал JavaScript или иной код приложения. В Python использованы `int`, regex canonical суммы и `datetime.date.fromisoformat`.
5. Отдельно для каждого из 13 valid cases заново отобраны `ledgerRecords` по неудалённости, месяцу и валюте, удалено только тестовое DB-поле `deleted`; полученный массив целиком сравнен с `state.records`. Это проверка входного эталона native-отбора, не доказательство запуска native. Далее доходы исключены из диаграммы, но проверены собственные summary.income/net.
6. Заново построены все группы, их exact minor/amount, remainder, basisPoints, percent, затем sectors/memberKeys/startUnit/endUnit/widthUnits/zeroWidth/amount/percent; поля сравнены с JSON с сохранением JSON-типов. Шесть malformed состояний пропущены через проверки дублей ID, валюты, scale, категории, суммы и равенства итога: все отклонены, как ожидается.
