# APP-014: извлечение и предзаполнение банковского уведомления

2026-11-04, Asia/Qyzylorda. Исполнитель `/root/bank_capture_engineer`, backend-engineer; задание chief от имени `/root/import_backend_lead`. Прочитаны полный профиль, AGENTS.md, PROTOCOL и план главы. Это реализация узкого объёма, не независимый QA и не собственная приёмка.

## Выполненное

- `NotificationText` — чистый Java assembler title/bigText/text/textLines. Все непустые варианты доступны разбору, даже при наличии короткого body. Только равное целое представление либо его точная последовательность целых строк в другом представлении исключается. Отдельные одинаковые суммы и повторы строк внутри одного представления сохраняются: две операции не становятся одной. Различные или противоречивые варианты остаются вместе и требуют review. Источник/результат ограничены 65536 символами, длина массива строк тоже ограничена; превышение не создаёт финансовую запись с выдуманными полями.
- Service вызывает assembler после прежних проверок профиля/доступа/настроек/выбранного пакета; group summary по-прежнему пропускается. Ненужные старые append/TextLimit удалены, новый limit обрабатывается прежним unavailable-кандидатом. Текст не сохраняется и не логируется.
- Только `BankMessageParser`: отдельные слова тг/тенге/теңге нормализуются в KZT; сумма обрабатывается существующим exact Money, без округления или валюты из настройки. Для нового неподтверждённого формата добавляется существующий `LOW_CONFIDENCE`: получаются поля для review, а не новое автоматическое правило неизвестного банка. Старый ParserTest, требующий review для «Покупка 123.45 тг», сохранён без замены ожидания.
- Явные «Вы перевели/отправили», «Вам перевели/отправили», «Получен перевод», «Перевод получен/зачислен», ограниченные английские формы дают направление для review. Эти новые формы сами добавляют `UNSUPPORTED_EVENT`, даже когда общее слово «перевод» отсутствует. «Переведено» без направления и распознанные свои счета не выдают направление. Общие guards отмены/отрицания/неокончательности не ослаблены.
- `ParseSupport`, ReceiptParser/старые тесты, storage, SourceTokens, NativeRuntime, build.gradle и соседние QR-файлы не редактировались.

## Ограничения и следующий этап

APP14-B01: конкретный пропущенный пользовательский payload не предоставлен; bank-specific automatic coverage не доказана. APP14-B02: отсутствующие OS уведомления исходящего Kaspi не появляются из parser и по-прежнему недоступны. Переводы, свои счета, комиссия/несколько сумм и неподтверждённые алиасы требуют проверки; улучшено предзаполнение, а не обещан полный автоматический учёт. Баланс по прежнему консервативному контракту также сохраняет review. Изменение assembled text может изменить HMAC revision; прежние storage механизмы защиты повторов намеренно не менялись.

Следующее действие: отдельная проверка главой и специалистом идентичности, затем сборка реального Android service, независимый QA новой версии и суд. APK не собирался и на телефоны не устанавливался этим исполнителем.
